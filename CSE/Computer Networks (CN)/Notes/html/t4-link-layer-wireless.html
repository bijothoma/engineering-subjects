Link Layer, Wireless and Mobility

Unit 4 (weeks 11-13) · Kurose & Ross Ch. 6 (Link layer and LANs), Ch. 7 (Wireless and mobile networks), Ch. 8 (Security, intro); multimedia networking and network management as per syllabus · also Peterson-Davie Ch. 2, Tanenbaum Ch. 3-4

1. Link layer services (K&R 6.1)

Definition. Nodes (hosts, routers, switches, APs) are connected by links (wired, wireless, LAN). A layer-2 PDU is a frame; it encapsulates a datagram and moves it over one hop. The link layer is implemented in the adapter / NIC (hardware + firmware, plus the driver in the host's OS).
  • Framing and link access: add header/trailer, MAC (physical) addresses, channel access rules for shared media.
  • Reliable delivery between adjacent nodes: rarely done on low-error links (fibre, twisted pair, Ethernet); common on wireless (high error rate; 802.11 uses ACK + retransmission).
  • Flow control between sender and receiver, error detection (CRC) and error correction, half/full duplex.
Datagram (IP) --> [ H | datagram | CRC ] frame --> link --> strip H,CRC --> datagram
Different links on a path may use different link protocols (Ethernet, 802.11, PPP).

2. Error detection and correction (K&R 6.2)

2.1 Parity

Single parity bit: even parity makes the number of 1s (data + parity) even. Detects any odd number of bit errors; misses even numbers. Two-dimensional parity: data arranged in i rows and j columns with a parity bit per row and column (plus corner bit). Detects and corrects any single-bit error (row and column parity both fail at the error location) and detects any 2-bit error (cannot always correct it).

Example (even parity). Row 1011 → parity 1 (three 1s); row 0110 → 0; row 1110 → 1. Column parities: col1 = 1+0+1 → 0, col2 = 0+1+1 → 0, col3 = 1+1+1 → 1, col4 = 1+0+0 → 1. Flip a data bit: its row and column parity checks both fail, which locates and fixes it.

2.2 Internet checksum (K&R 3.3, reused)

Treat data as 16-bit words, add in one's-complement (wrap carry around), complement the sum. Receiver adds all words incl. checksum; result must be all 1s.

Example. 0x6660 + 0x5555 + 0x8F0C = 0x14AC1 → wrap carry: 0x4AC1 + 1 = 0x4AC2 → checksum = ~0x4AC2 = 0xB53D. Check: 0x4AC2 + 0xB53D = 0xFFFF.

2.3 Cyclic Redundancy Check (CRC)

Idea. Treat D (d bits) as a polynomial. Choose a generator G of r+1 bits (MSB = 1). Sender appends r bits R so that (D·2r XOR R) is exactly divisible by G (modulo-2 arithmetic, no carries). Equivalent: R = remainder of D·2r / G.
CRC(D, G):
  M = D followed by r zeros
  for i = 0 .. len(D)-1:
      if M[i] == 1: XOR G into M starting at position i
  R = last r bits of M          // transmit D followed by R
Receiver: divide received (D,R) by G; remainder != 0  =>  error.

Worked example. D = 101110, G = 1001 (r = 3). M = 101110000.

101110000
XOR 1001 at pos 0  -> 001010000
XOR 1001 at pos 2  -> 000011000
XOR 1001 at pos 4  -> 000001010
XOR 1001 at pos 5  -> 000000011      R = 011
Transmitted: 101110 011

Second example: D = 1101011011, G = 10011 (x⁴+x+1) → R = 1110; frame 11010110111110. Third: D = 11010011101100, G = 1011 → R = 100. (All checked by computation.)

Guarantees. With r check bits, CRC detects all burst errors of length ≤ r, all odd numbers of errors if (x+1) divides G, and bursts longer than r with probability 1 - 2-r. Ethernet uses CRC-32; 802.11 too. Computed in hardware by shift registers (XOR gates).
Pitfalls. Subtraction = XOR; the remainder has exactly r bits (keep leading zeros); CRC detects but does not correct; checksum (software, transport) vs CRC (hardware, link).

3. Multiple access protocols (K&R 6.3)

A broadcast channel shared by many nodes needs a MAC protocol: simultaneous transmissions collide. Ideal: rate R bps, one node gets R, M nodes get R/M each, decentralised, simple. Three classes:

TDMA/FDMA: no collisions but unused slots are wasted and a lone node gets only R/N.

3.1 Slotted ALOHA

Assumptions: equal frames, time in slots (1 frame), start only at slot boundaries, nodes detect collisions.
Node: new frame -> send in next slot.
      no collision -> success; collision -> retransmit in each later slot with probability p until success.

N nodes each transmit with prob. p: P(a given node succeeds) = p(1-p)N-1; P(some node succeeds) = Np(1-p)N-1. Maximised at p = 1/N. For N = 4, p = 1/4: 4 × 0.25 × 0.75³ = 0.4219. As N → ∞: 1/e ≈ 0.368 (N=10: 0.387; N=100: 0.370). Hence at most 36.8% of slots are useful; 37% empty, 26% collisions.

3.2 Pure (unslotted) ALOHA

Transmit immediately. A frame at t₀ collides with any frame starting in (t₀-1, t₀+1): vulnerable period is 2 frame times. P(success) = p(1-p)2(N-1); max efficiency = 1/(2e) ≈ 0.184 (half of slotted).

3.3 CSMA and CSMA/CD

CSMA: "listen before talk" (carrier sense); if idle, transmit whole frame, else defer. Collisions still happen because of propagation delay: a node may not yet hear another's transmission. CSMA/CD adds collision detection: abort transmission as soon as another transmission is sensed (needs listening while sending - easy on wired, hard on wireless).

Ethernet CSMA/CD (adapter):
 1. get datagram, build frame
 2. sense channel: if idle, start transmitting; if busy, wait until idle then transmit
 3. if whole frame sent with no collision detected: done
 4. if collision detected: abort, send 48-bit JAM signal
 5. binary exponential backoff: after the m-th collision (m capped at 10)
    choose K uniformly from {0,1,...,2^m - 1}; wait K x 512 bit times; go to step 2
    (give up after 16 attempts)

Why it works: early collisions → small K range (low delay); many collisions → larger range (adapts to load). After the 3rd collision K ∈ {0..7}.

Minimum frame / slot time. A sender must still be transmitting when the collision signal returns after one round trip (2·tprop). Ethernet: 512 bits = 64 bytes min frame; at 10 Mbps that is 51.2 µs (at 100 Mbps 5.12 µs). With signal speed 2×10⁸ m/s, 51.2 µs ⇒ 2d/v ≤ 51.2 µs ⇒ d ≤ 5.12 km (the real 2.5 km limit leaves margin for repeaters and the jam signal).

CSMA/CD efficiency ≈ 1 / (1 + 5·dprop/dtrans), where dprop = max propagation delay between nodes, dtrans = time to send a max-size frame. Efficiency → 1 as dprop → 0 or dtrans → ∞. Example: dprop = 10 µs, dtrans = 50 µs → 1/(1+1) = 0.5.

3.4 Taking turns

Polling: master polls slaves (poll overhead, latency, single point of failure; Bluetooth). Token passing: control token circulates (token overhead, loss/failure of a node can halt the ring; FDDI, token ring).

3.5 CSMA/CA (preview; details in section 9)

Collisions cannot be detected on wireless; so avoid them: random backoff, link-layer ACK, optional RTS/CTS.

4. LANs: addressing, ARP, Ethernet (K&R 6.4)

4.1 MAC addresses

48-bit, written as 6 hex bytes (1A-2F-BB-76-09-AD), burned into the NIC, flat, portable; first 24 bits = manufacturer (OUI). Broadcast = FF-FF-FF-FF-FF-FF. IP address = hierarchical, location-dependent; MAC address = flat, identifies the interface.

4.2 ARP (Address Resolution Protocol)

Maps IP → MAC within one subnet. Each node keeps an ARP table (IP, MAC, TTL ≈ 20 min). If missing: broadcast an ARP query (dest MAC FF-FF-FF-FF-FF-FF) asking "who has IP X?"; the owner replies with a unicast ARP reply. Plug-and-play.

send(A -> B, same subnet):  look up B in ARP table;
   miss -> broadcast ARP query; B replies; cache; send frame to B's MAC
send(A -> B, different subnet): ARP for the first-hop router's interface MAC (default gateway);
   frame: src MAC = A, dst MAC = router R's interface; IP dst = B.
   R decapsulates, forwards, ARPs on the outgoing subnet, re-frames (new MACs; IP addresses unchanged).
Pitfall. End-to-end IP addresses stay the same; MAC addresses change at every hop. ARP does not cross routers. ARP has no authentication (spoofing/poisoning attacks).

4.3 Ethernet frame

| Preamble 8B | Dest MAC 6B | Src MAC 6B | Type 2B | Data 46-1500B | CRC 4B |

Preamble: 7 bytes 10101010 + SFD 10101011 for clock sync. Type: higher-layer protocol (IP 0x0800, ARP 0x0806). Data padded to ≥ 46 bytes ⇒ frame 64-1518 bytes (header+data+CRC). A frame with bad CRC is dropped silently. Connectionless and unreliable - no handshake, no ACK; reliability (if any) comes from TCP. Shared medium uses unslotted CSMA/CD with binary backoff.

4.4 Ethernet technologies

10Base2/10Base5 (coax bus, one collision domain), 10BaseT/100BaseT (twisted pair, star with hub, later switch), 1000BaseT, fibre (100BaseFX, 10GBase-SR). Same frame format since the 1970s; speeds 10 Mbps to 400 Gbps. Modern LANs use switches with full-duplex links, so there are no collisions and CSMA/CD is effectively unused.

5. Hubs, bridges, switches (K&R 6.4.3)

  • Hub (layer 1): repeats bits on all ports; one collision domain; dumb.
  • Bridge / switch (layer 2): store-and-forward Ethernet frames; examine the dest MAC and selectively forward; separates collision domains; transparent (hosts unaware) and plug-and-play, self-learning.

Each switch port has a dedicated link: frames are buffered, no collisions, full duplex. A switch has a switch table: (MAC, interface, TTL).

Frame arrives on interface i with source S, destination D:
  table[S] = (i, now)                 // self-learning
  if D is in table:
       if table[D].iface == i: drop frame        // same segment (filtering)
       else forward on table[D].iface
  else flood on all interfaces except i          // unknown or broadcast
Entries age out after a timeout.

Example. A→A' (A' unknown): flood; learn A on port 1. A'→A: learn A' on port 4; A known → forward only to port 1. Switches may be interconnected in a tree; learning still works in a loop-free topology (the spanning tree protocol is needed with redundant paths to avoid broadcast storms).

6. VLANs (K&R 6.4.4)

A Virtual LAN lets one physical switch (or several) behave as multiple logical LANs: ports are grouped (port-based VLAN), giving traffic isolation (broadcasts stay within the VLAN), dynamic membership, and ease of management. Inter-VLAN traffic must go through a router (or layer-3 switch). A trunk port between switches carries frames of many VLANs, using the 802.1Q tag: 4 bytes inserted after the source address = 2-byte TPID (0x8100) + 3-bit priority + 1-bit DEI + 12-bit VLAN ID (4094 usable IDs). The CRC is recomputed.

7. MPLS and link virtualisation (K&R 6.5-6.7)

Multiprotocol Label Switching: a "layer 2.5" 32-bit header placed between link header and IP header: 20-bit label, 3-bit Exp/CoS, 1-bit bottom-of-stack S, 8-bit TTL. MPLS routers forward by exact-match label lookup (like virtual circuits) and swap the label, not by longest-prefix matching. Label-switched routers (LSRs) are IP-capable routers that use signalling (RSVP-TE, LDP) to build label-switched paths (LSPs). Benefits: traffic engineering (route flows on paths plain IP/OSPF would not choose, e.g. split load over two paths), fast reroute, VPNs.

Ingress LSR: classify packet, push label 10 -> core LSR: label 10 -> label 6, port 1 -> egress LSR: pop label -> IP forwarding

Link virtualisation: other networks (ATM, MPLS) act as a single logical link for IP. Data centre networks: leaf-spine / fat-tree topologies; racks with Top-of-Rack switches, load balancer at the border, rich multipath interconnection.

A day in the life of a web request (K&R 6.7): connect laptop → DHCP (UDP broadcast, gets IP, gateway, DNS) → ARP for the gateway MAC → DNS query for the server → TCP handshake → HTTP GET. Uses DHCP, UDP, IP, Ethernet/802.11, ARP, DNS, TCP, HTTP.

8. Wireless links and networks (K&R 7.1-7.2)

Elements: wireless hosts, base station / access point (relay between wired and wireless), wireless link. Modes: infrastructure (via AP/cell tower; handoff when moving) vs ad hoc (no infrastructure; nodes route among themselves).

Differences from wired: decreasing signal strength (path loss), interference from other sources in the same band (2.4 GHz: microwave ovens, Bluetooth), multipath propagation (reflections). Hence higher bit error rates, and an SNR/BER trade-off: for a given modulation, higher SNR lowers BER; for a given SNR, a higher-rate modulation has higher BER; so adapt modulation to the channel (rate adaptation).

Hidden terminal problem. A and C both reach B but cannot hear each other (distance or obstacle) → they transmit simultaneously and collide at B. Exposed terminal: B hears C and defers though its transmission to A would not disturb C's receiver. Also fading: a node cannot sense all collisions, so collision detection is not feasible and CSMA/CD is not used.

CDMA

Each user has a unique chipping code (M chips per data bit). Sender sends di·cm; receiver recovers di = (1/M) Σ Zm·cm with orthogonal codes; users overlap in time and frequency. Example: M = 8, c = (1,1,1,-1,1,-1,-1,-1); data bit +1 sends c; data bit -1 sends -c; inner product with c gives (1/8)·8·d = d, with another orthogonal code gives 0.

9. IEEE 802.11 WiFi (K&R 7.3)

Standards: 802.11b (2.4 GHz, 11 Mbps), a (5 GHz, 54), g (2.4, 54), n (2.4/5, MIMO, up to 600), ac (5 GHz, multi-gigabit), ax/WiFi 6 (OFDMA). All use CSMA/CA and share the frame format; backward compatible.

Architecture. BSS (basic service set) = AP + hosts. An AP has an SSID and channel (2.4 GHz band: 11 channels in the US, only 1, 6, 11 non-overlapping). A host must associate with an AP: passive scanning (listen for beacon frames) or active scanning (probe request → probe response), then association request/response, authentication (WPA2/WPA3), then DHCP for an IP. Ad hoc: IBSS.

9.1 CSMA/CA

Sender:
 1. if channel idle for DIFS: transmit the entire frame (no collision detection)
 2. else: pick random backoff counter; decrement only while channel idle (freeze when busy);
    when counter = 0: transmit; if no ACK: double the contention window, retry
Receiver: if frame OK, after SIFS (< DIFS) send ACK.
 (needed since hidden terminals mean the sender cannot know about collisions)

RTS/CTS (optional): sender transmits a short RTS to the AP (collisions then involve only short frames); the AP broadcasts CTS, heard by all hidden nodes, which defer for the duration (NAV, virtual carrier sensing); then DATA, ACK. Overhead is worthwhile for long frames/hidden terminals.

9.2 802.11 frame

Frame control (type, subtype: data/RTS/CTS/ACK/management, to/from-AP flags), duration, four address fields: Address 1 = receiver MAC (wireless host or AP), Address 2 = transmitter MAC, Address 3 = MAC of the router interface to which the AP is attached (so the AP can build the Ethernet frame), Address 4 used only in ad hoc mode; sequence control (for duplicate detection when ACKs are lost), payload up to 2312 B, CRC. For a frame from H1 to R1 via AP: Addr1 = AP, Addr2 = H1, Addr3 = R1; the AP then sends an 802.3 frame with dest = R1, src = H1.

9.3 Mobility within the same subnet; other features

If AP1 and AP2 are in the same IP subnet connected via a switch, the host can roam: it re-associates with the new AP, which sends a frame with the host's MAC so the switch updates its table (self-learning) - the IP address does not change. Features: rate adaptation (drop to a lower rate when BER rises), power management (node sleeps, tells the AP via a power-management bit, wakes before the next beacon). 802.15 personal-area networks: Bluetooth (ad hoc piconet, TDM, 2.4 GHz, frequency hopping, master/slave polling), Zigbee (low power).

10. Cellular networks (K&R 7.4)

Architecture: base station (BTS/eNodeB) covering a cell; MSC / core network connects to the telephone network and Internet. Air-interface multiple access: FDMA/TDMA combination (2G GSM), CDMA (3G), OFDMA (4G LTE). 4G: all-IP core (EPC) with S-GW/P-GW, MME and HSS (home subscriber server stores profile and location); 5G adds mm-wave and network slicing. Neighbouring cells use different frequencies (frequency reuse).

11. Mobility management (K&R 7.5-7.7)

Terms: home network (permanent address), home agent, visited (foreign) network, foreign agent, correspondent, care-of address (COA).

Approaches: let routers advertise the host's /32 (does not scale); indirect routing - the correspondent sends to the permanent address; the home agent encapsulates (tunnels) to the COA; the mobile replies directly: triangle routing (inefficient, but transparent to the correspondent, and connections survive moves because only the home agent is updated). Direct routing - the correspondent first asks the home agent for the COA, then tunnels directly (efficient, but not transparent; on a move, an anchor foreign agent forwards to the new location).

Mobile IP (RFC 5944): 1. agent discovery (advertisement/solicitation, ICMP)
 2. registration with home agent (COA, lifetime)
 3. datagram: correspondent -> home network -> (IP-in-IP tunnel) -> COA -> mobile

Cellular handoff: measured signal strength → the old BS asks the MSC to set up a path via the new BS (the anchor MSC stays fixed for the call; later MSCs are chained); allocate channel, new BS tells mobile, mobile switches. Impact on higher layers: TCP misreads wireless loss/handoff loss as congestion and cuts its rate (remedies: split connection, local retransmission, snoop, FEC); delay variation hurts multimedia.

12. Visible Light Communication (intro)

VLC / Li-Fi: data is sent by modulating the intensity of LEDs at rates imperceptible to the eye (visible light 380-780 nm, ≈ 400-790 THz), received with photodiodes or camera sensors. Modulation: OOK (on-off keying), PPM, OFDM. Advantages: huge unlicensed spectrum, no RF interference, secure (confined by walls), high capacity, reuses lighting infrastructure. Limits: needs line of sight (or reflections), light must be on (dimming via PWM), blockage, ambient light noise, short range, uplink needs IR/RF. Applications: hospitals, aircraft, underwater, indoor positioning, vehicle lights (IEEE 802.15.7, 802.11bb).

13. Multimedia networking (K&R Ch. 9, intro)

  • Classes: streaming stored audio/video (YouTube, Netflix: client buffering, tolerates start-up delay; HTTP-based DASH: video encoded at multiple bit rates in chunks, manifest file, client adaptively requests chunks by estimated throughput; CDNs), conversational voice/video over IP (VoIP: delay < 150 ms good, > 400 ms bad; tolerates some loss), live streaming.
  • Audio: sample (8000/s) and quantise (PCM 8 bit → 64 kbps); video: pixel arrays, spatial and temporal compression (MPEG, H.264).
  • Jitter is removed by a playout delay at the receiver: sequence numbers + timestamps; fixed or adaptive playout (adjust at talk-spurt start). Loss: FEC, interleaving, concealment. The best-effort Internet gives no guarantees.
  • Protocols: RTP (over UDP; payload type, sequence number, timestamp, SSRC; gives no QoS), RTCP (reports on loss, jitter, delay; limited to about 5% of session bandwidth), SIP (session set-up, locating callee), H.323. Network support: packet scheduling (priority, WFQ), policing (token bucket: average rate, peak rate, burst size), DiffServ, IntServ/RSVP (call admission).

Example (jitter buffer). Packets generated every 20 ms; playout delay q = 100 ms; packet k is generated at 20k ms and played at 20k + 100. A packet with network delay 90 ms is in time; with 130 ms it is late (treated as lost).

14. Network management (K&R 5.7, intro)

Components: managing server (with network manager), managed device with managed objects, agent, and a management protocol. SNMP: request/response (GetRequest, GetNextRequest, GetBulk, SetRequest, Response) plus agent-initiated Trap messages; over UDP (161; traps 162). MIB = Management Information Base; objects described by SMI and named by OIDs, encoded with ASN.1/BER. NETCONF/YANG: XML-based, transactional configuration over SSH/TLS. Also syslog, SDN-based management, telemetry. Functions: fault, configuration, accounting, performance, security (FCAPS).

15. Network security (K&R Ch. 8, intro)

Goals: confidentiality, integrity, authentication, availability / non-repudiation. Attacks: eavesdrop, insert/delete messages, impersonate (spoof), hijack, denial of service (DoS/DDoS), malware.

  • Symmetric cryptography: shared key K; DES (56-bit, broken), AES (128/192/256-bit); block ciphers with CBC chaining (IV).
  • Public-key: RSA - choose primes p, q; n = pq, z = (p-1)(q-1); e coprime to z; d with ed ≡ 1 (mod z); encrypt c = me mod n; decrypt m = cd mod n. Example p = 5, q = 7: n = 35, z = 24, e = 5, d = 29; m = 12: c = 12⁵ mod 35 = 17; 17²⁹ mod 35 = 12. Slow, so typically used to exchange a session key.
  • Integrity: hash (SHA-256), MAC / HMAC; digital signature: sign the hash with the private key, verify with the public key; certificates bind a public key to an identity (CA).
  • Authentication: replay defeated by a nonce (challenge-response).
  • Secure protocols: TLS (handshake: negotiate algorithms, certificate, key derivation; record protocol with MAC), IPsec (AH, ESP; transport and tunnel mode; VPN), WPA2/WPA3 for WiFi (WEP is broken by RC4 key-stream reuse), PGP for email.
  • Operational security: firewalls (stateless packet filters, stateful, application gateways), IDS/IPS.
  • Link-layer attacks: MAC flooding, ARP spoofing, rogue AP, VLAN hopping.

Quick revision

  • Link layer: frames over one hop; the adapter implements it; services: framing, access, optional reliability, error detection.
  • Even parity detects odd bit errors; 2-D parity corrects 1-bit errors. Checksum = one's-complement sum; CRC remainder of D·2r mod G (e.g. 101110/1001 → 011).
  • Slotted ALOHA max 1/e = 0.368 (p = 1/N); pure ALOHA 1/(2e) = 0.184; success Np(1-p)N-1; CSMA/CD efficiency ≈ 1/(1 + 5 dprop/dtrans).
  • Ethernet: 64-1518 B frames, backoff K ∈ {0..2m-1} × 512 bit times; min frame 64 B so the sender detects a collision; unreliable, connectionless.
  • ARP: broadcast query, unicast reply, local subnet only. MACs change per hop, IPs do not.
  • Switch: self-learning, filter/forward/flood; separates collision domains; VLAN separates broadcast domains (802.1Q 12-bit ID); MPLS: label swapping + traffic engineering.
  • Wireless: path loss, interference, multipath; hidden terminal; 802.11 uses CSMA/CA + ACK + optional RTS/CTS; four address fields; non-overlapping channels 1, 6, 11.
  • Mobility: home/foreign agent, COA; indirect routing (triangle, transparent) vs direct routing (efficient, less transparent); cellular handoff via MSC.
  • VLC: LED intensity modulation; line of sight, secure, no RF interference.
  • Multimedia: jitter → playout buffer; RTP/RTCP/SIP; DASH. Management: SNMP, MIB, traps. Security: confidentiality, integrity, authentication; AES, RSA, HMAC, TLS, IPsec, firewalls.
