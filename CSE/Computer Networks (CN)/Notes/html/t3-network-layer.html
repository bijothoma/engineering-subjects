Network Layer

Weeks 9-10 · Kurose & Ross (6/e) Ch. 4, and the later-edition split into Ch. 4 (data plane) and Ch. 5 (control plane) · Peterson-Davie Ch. 3-4 · Tanenbaum Ch. 5

1. Network layer services and the two planes

Definition. The network layer moves a segment from the sending host to the receiving host, hop by hop through routers. Two functions: forwarding (data plane: move a packet from a router's input link to the right output link, nanosecond-scale, in hardware) and routing (control plane: compute the end-to-end path and fill the forwarding tables, seconds-scale, in software).
  • Per-router control plane: every router runs a routing algorithm and talks to its neighbours (traditional). Logically centralised (SDN): a remote controller computes tables and installs them in routers.
  • Service model of the Internet: best effort: no guarantee of delivery, order, bounded delay or minimum bandwidth. (ATM CBR/ABR offered guarantees; they lost.) Simplicity at the core, intelligence at the edge.
  • Datagram network (Internet): forwarding by destination address, no per-flow state in routers. Virtual-circuit network (ATM, MPLS-like, frame relay): call setup, a VC number on each link that is swapped at every router; router keeps per-connection state. A VC table is small; a datagram table needs longest-prefix matching.
  • ICMP (carried in IP) reports errors: destination unreachable, time exceeded (TTL hit 0), echo. traceroute sends probes with TTL = 1, 2, 3 ... and reads the "time exceeded" replies.

2. Router architecture

Four parts: input ports (physical termination, link-layer, then lookup in a local copy of the forwarding table), switching fabric, output ports (buffer, scheduler, link transmit), and the routing processor (control plane: runs routing protocols, computes and installs tables, management).

Queuing

  • Input queuing: if the fabric is slower than the sum of input rates, packets queue at input. Head-of-line (HOL) blocking: the packet at the front is waiting for a busy output and blocks packets behind it that want idle outputs.
  • Output queuing: arrival rate to one output can exceed the line rate (fabric faster than the line). Buffer overflow means packet loss, which is where Internet loss mostly happens. A scheduler (FIFO, priority, round robin, WFQ) picks the next packet; a drop policy (tail drop, RED) picks the victim.
  • Buffer sizing: classic rule B = RTT × C. Recent rule for N long-lived flows: B = RTT × C / √N. Example: RTT = 250 ms, C = 10 Gbps, N = 10,000: RTT·C = 2.5 Gbit, divided by √N = 100 gives 25 Mbit.
Pitfall. Longest-prefix matching is done at the input port (by TCAM in hardware), not by the routing processor. The routing processor only builds the table.

3. IPv4

  • IHL counts 32-bit words: min 5 = 20 bytes; value 7 = 28 bytes (8 bytes of options). Max 15 = 60 bytes.
  • Protocol: 6 = TCP, 17 = UDP, 1 = ICMP, 89 = OSPF, 41 = IPv6-in-IPv4. TTL is decremented at each router; at 0 the packet is dropped and ICMP time-exceeded returned. Header checksum is recomputed at each hop (TTL changes).

Fragmentation

Each link has an MTU. A router fragments a datagram bigger than the outgoing MTU; only the destination host reassembles. All fragments share the identification; MF = 1 on all but the last; the offset is in units of 8 bytes, so every fragment except the last carries a data length that is a multiple of 8.

Worked example. 4000-byte datagram (20 header + 3980 data), MTU 1500. Max data per fragment = 1480 (multiple of 8). Fragments: (1500 B, offset 0, MF=1), (1500 B, offset 1480/8 = 185, MF=1), (1040 B = 20 + 1020, offset 2960/8 = 370, MF=0).
Pitfall. Forgetting to subtract the 20-byte header (data per fragment is 1480 not 1500), and writing the offset in bytes instead of 8-byte units. IPv6 forbids fragmentation by routers; hosts use Path MTU Discovery.

4. IPv4 addressing, subnetting, CIDR

An address is 32 bits, written as four decimal bytes. An interface (not a host) has an address. A subnet is a set of interfaces that can reach each other without a router; the high-order bits are the common prefix. CIDR (RFC 4632) writes a network as a.b.c.d/x: the first x bits are the network prefix and the remaining 32-x are host bits. Classful A/B/C boundaries are obsolete.

  • Addresses in /x block: 232-x; usable hosts 232-x - 2 (all-zeros host = network address, all-ones host = directed broadcast). 255.255.255.255 is the limited broadcast.
  • Mask 255.255.255.192 = 11111111.11111111.11111111.11000000 = /26. Block size in the last octet = 256 - 192 = 64.
  • Private ranges (RFC 1918): 10/8, 172.16/12, 192.168/16. Loopback 127/8. Multicast 224/4.

Procedure (subnet of an address)

network   = address AND mask
broadcast = network OR (NOT mask)
hosts     = network+1 .. broadcast-1      (2^(32-x) - 2 of them)
Worked example 1. 192.168.10.77/26: block size 64, 77 lies in [64,127]. Network 192.168.10.64, broadcast 192.168.10.127, usable 65..126 = 62 hosts.
Worked example 2. 130.50.15.6/20: third octet 15 = 00001111, mask keeps the top 4 bits (0000) so network = 130.50.0.0, broadcast = 130.50.15.255.
Worked example 3. 172.16.0.0/16 with mask 255.255.252.0 (/22): 6 extra bits give 26 = 64 subnets, each with 210 - 2 = 1022 hosts.

VLSM and aggregation

VLSM: different subnets get different prefix lengths. Method: sort requirements largest first, give each the smallest block 2k ≥ hosts + 2, align on its size. For 192.168.1.0/24 with 100, 50, 25 hosts: 100 needs /25 (126), 50 needs /26 (62), 25 needs /27 (30). Allocation 192.168.1.0/25, 192.168.1.128/26, 192.168.1.192/27 (no overlap; 192.168.1.224/27 is spare).

Route aggregation (supernetting): advertise one shorter prefix for many contiguous, aligned blocks. 192.168.0.0/24 .. 192.168.3.0/24 aggregate to 192.168.0.0/22. The blocks 172.16.4.0/24, .5, .6 need 172.16.4.0/22, which also covers 172.16.7.0/24; the aggregate is only exact for a power-of-two count of aligned blocks.

Pitfall. The prefix must be aligned: 172.16.6.0/22 is not a valid network address (it would be 172.16.4.0/22). Do not mix the "2 reserved addresses" rule into the number of subnets with CIDR (all subnets usable).

5. Forwarding and longest-prefix match

Forwarding table maps prefixes to output interfaces (and next hop). The router picks the entry with the longest matching prefix; the default route is 0.0.0.0/0.

forward(dest):
  best = none
  for each entry (prefix, len, port) in table:
      if (dest AND mask(len)) == prefix and (best is none or len > best.len):
          best = entry
  return best.port        // default route (len 0) matches everything

Naive scan is O(entries); binary trie lookup is O(32) (O(W) for W-bit addresses); hardware uses TCAM (one-cycle parallel match).

Worked example. Table: 10.0.0.0/8 → A, 10.1.0.0/16 → B, 10.1.2.0/24 → C, 10.1.2.64/26 → D, default → E.
10.1.2.77 matches /8, /16, /24 and /26 (77 in 64..127) → D. 10.1.2.200 matches up to /24 → C. 10.1.9.9 → B. 10.200.1.1 → A. 11.0.0.1 → E (default).

Generalised forwarding (SDN) matches on many header fields, not only the destination.

6. DHCP

Dynamic Host Configuration Protocol (UDP, server port 67, client port 68) gives a host an IP address, subnet mask, first-hop router and DNS server automatically; the address is leased for a time and renewed. Plug-and-play; a DHCP relay agent lets one server serve many subnets.

1. DHCP DISCOVER  client -> 255.255.255.255:67, src 0.0.0.0
2. DHCP OFFER     server -> client (broadcast): yiaddr, mask, lease
3. DHCP REQUEST   client -> broadcast: accepts one offer
4. DHCP ACK       server -> client: confirms; client may use the address

Step 3 is broadcast so that other servers learn their offers were not taken.

7. NAT

A NAT router gives a whole private network (e.g. 10.0.0.0/24) one public address. Outbound: replace (private IP, port) by (public IP, new port) and record in the NAT translation table. Inbound: look up the destination port in the table and rewrite back.

Example. Host 10.0.0.1:3345 sends to 128.119.40.186:80. NAT (public 138.76.29.7) rewrites the source to 138.76.29.7:5001 and stores {5001 ↔ 10.0.0.1:3345}. Reply to 138.76.29.7:5001 is rewritten to 10.0.0.1:3345. The 16-bit port field allows about 216 = 65,536 (≈64k) simultaneous connections per public address.
Controversy. Ports are for processes, not hosts; routers should not look above the network layer; it violates the end-to-end argument and blocks inbound connections to servers behind it (needs static port mapping, UPnP or NAT traversal). IPv6 removes the need for NAT.

8. Software-Defined Networking, OpenFlow, P4

  • SDN: control plane is separated from the data plane; a logically centralised controller (with a network-control application on top) talks to switches over a southbound API such as OpenFlow, and to applications over a northbound API.
  • OpenFlow match-plus-action: each flow-table entry has header fields to match (link, network and transport layer: MAC, IP, ports, VLAN...), counters, and actions: forward, drop, modify field, send to controller. One abstraction unifies router, switch, firewall and NAT. Messages: controller-to-switch (features, configure, modify-state, packet-out), asynchronous (packet-in, flow-removed, port-status), symmetric (hello, echo).
  • P4: a language to program how the data plane processes packets: define the headers to parse, the match-action tables and the control flow of the pipeline; protocol independent, target independent (compiled for the switch ASIC/NIC/software switch). OpenFlow fixes the header fields; P4 lets you define them.

9. Routing: link state and distance vector

Network = graph with link costs c(u,v). Goal: least-cost path from each router to every other. Global (link state): everyone knows the whole graph. Decentralised (distance vector): iterative exchange with neighbours.

9.1 Link-state: Dijkstra

Each router floods its link costs (link-state broadcast); then each router runs Dijkstra locally.

Dijkstra(source u):
  N' = {u}
  for all v: D(v) = c(u,v) if adjacent else INF ; p(v) = u
  D(u) = 0
  repeat until N' = all nodes:
      pick w not in N' with minimum D(w); add w to N'
      for each neighbour v of w not in N':
          if D(w) + c(w,v) < D(v): D(v) = D(w) + c(w,v); p(v) = w

Correctness idea: when w is moved into N', D(w) is the true shortest distance, because any other path must leave N' through some node whose tentative distance is ≥ D(w) and costs are non-negative. Complexity: n nodes, linear scan: n + (n-1) + ... = n(n+1)/2 = O(n2); binary heap: O(E log n). Message complexity of flooding: O(nE) messages. Oscillation can occur if link cost depends on load.

Worked example. Graph: u-v 2, u-x 1, u-w 5, v-x 2, v-w 3, x-w 3, x-y 1, w-y 1, w-z 5, y-z 2. From u:
StepN'D(v),pD(w),pD(x),pD(y),pD(z),p

Shortest path u to z: u-x-y-z, cost 4. u's forwarding table: v via link (u,v); x, y, w, z via link (u,x). (v and y tie at cost 2; either order gives the same final result.)

9.2 Distance vector: Bellman-Ford

Bellman-Ford equation: Dx(y) = min over neighbours v of { c(x,v) + Dv(y) }. Each node keeps its own vector and its neighbours' vectors; whenever its own vector changes it sends it to neighbours. Asynchronous, iterative, self-terminating.

Bellman-Ford(source s):
  D(s)=0; D(v)=INF otherwise
  repeat |V|-1 times:
      for each edge (a,b,c): if D(a)+c < D(b): D(b)=D(a)+c   (and the reverse for undirected)

After round k the values are correct for all nodes whose shortest path has ≤ k edges. Complexity O(VE). In DV each round-trip costs O(degree) per node; convergence time varies.

Worked examples.
(a) x has neighbours y (cost 2), z (cost 7), v (cost 3). They report Dy(w)=4, Dz(w)=1, Dv(w)=5. Dx(w) = min(2+4, 7+1, 3+5) = 6, next hop y.
(b) Edges A-B 4, A-C 1, C-B 2, B-D 1, C-D 5; source A. Round 1: B=4, C=1. Round 2: B=3, D=5. Round 3: D=4 (path A-C-B-D has 3 edges). Stable after round 3.

Problems of distance vector

  • Good news travels fast, bad news slowly: count-to-infinity. With x-y 4, y-z 1, z-x 50: if cost(y,x) rises from 4 to 60, y switches to z (1 + Dz(x) = 1 + 5 = 6) not knowing z's path goes through y. y and z bounce the packet, increasing costs by 1 each round, until reaching 50 (via the direct z-x link).
  • Poisoned reverse: if z routes to x via y, z advertises Dz(x) = INF to y. Stops two-node loops but not loops among three or more nodes. Practical protocols also cap infinity (RIP: 16 = unreachable).

10. Routing in the Internet: autonomous systems

Scale and administrative autonomy are handled by grouping routers into autonomous systems (AS), each with an AS number. Intra-AS protocols (IGPs): RIP, OSPF, EIGRP, IS-IS. Inter-AS: BGP. Intra-AS focuses on performance; inter-AS also on policy. Forwarding table = intra-AS entries plus inter-AS entries for external prefixes.

RIP and OSPF

  • RIP: distance vector, cost = hop count, max 15 (16 = infinity), advertisements every 30 s, over UDP (port 520).
  • OSPF: link-state; flooding of link-state advertisements to the entire AS; Dijkstra on each router; costs set by administrator; messages carried directly over IP (protocol 89); authentication; multiple equal-cost paths; hierarchical with areas (a backbone area 0 and area border routers) to limit flooding.

BGP (path vector)

  • Pairs of routers exchange routes over semi-permanent TCP connections (port 179): eBGP between ASes, iBGP within an AS. A route = prefix + attributes: AS-PATH (list of ASes the advert traversed, also loop prevention), NEXT-HOP, LOCAL-PREF (policy), etc.
  • Route selection (in order): 1. highest LOCAL-PREF (policy); 2. shortest AS-PATH; 3. closest NEXT-HOP router (hot-potato routing: use the intra-AS least-cost path to leave the AS ASAP); 4. further tie-breakers (BGP identifiers).
  • Policy: an ISP exports routes to customers broadly but does not transit traffic between two providers; a stub network advertises only its own prefixes.
Example. Router sees route R1 (LOCAL-PREF 100, AS-PATH length 2) and R2 (LOCAL-PREF 200, AS-PATH length 5). R2 wins: policy precedes path length.
Pitfall. Hot-potato routing is the third rule, not the first; and BGP is a path-vector protocol (it carries the path, not just a distance) running over TCP, whereas OSPF runs straight over IP.

11. IPv6

  • 128-bit addresses (2128 ≈ 3.4 × 1038); written as 8 groups of 4 hex digits. Leading zeros in a group may be dropped and one run of all-zero groups replaced by "::" (only once): 2001:0db8:0000:0000:0000:ff00:0042:8329 = 2001:db8::ff00:42:8329. Trailing zeros inside a group (ff00) cannot be removed.
  • Fixed 40-byte header: version, traffic class, flow label (20 bits), payload length, next header, hop limit, source, destination. No header checksum (speed), no options in the base header (extension headers via next header), no fragmentation in routers (source fragments; ICMPv6 "packet too big"). ICMPv6 absorbs neighbour discovery and group management.
  • Transition: dual stack; tunneling: the IPv6 datagram is carried as the payload of an IPv4 datagram (protocol 41) between two IPv6 routers across an IPv4-only region, then decapsulated.

12. Multicast routing

One sender, many receivers, one copy per link. IPv4 class D range 224.0.0.0/4 (228 = 268,435,456 group addresses). Hosts join through IGMP (host to its local router: membership query / report / leave); routers build multicast trees with a multicast routing protocol (e.g. DVMRP, PIM).

  • Source-based tree: one tree per source (least-cost path tree). Group-shared tree: one tree per group (centre-based / rendezvous point).
  • Reverse path forwarding (RPF): on receiving a multicast datagram from source S on interface i, forward it on all other interfaces only if i is on the router's shortest unicast path back to S; otherwise drop. Avoids loops without per-packet state. Then pruning removes branches with no members.
  • PIM dense mode floods-and-prunes; PIM sparse mode builds trees explicitly towards a rendezvous point on join.

Quick revision

  • Forwarding (data plane, per packet) vs routing (control plane); Internet service is best effort.
  • Router = input ports + fabric (memory/bus/crossbar) + output ports + routing processor. HOL blocking at inputs; losses at output buffers; B = RTT·C/√N.
  • IPv4 header 20 B min, IHL in 32-bit words, fragment offset in 8-byte units, reassembly only at destination.
  • Subnet: network = addr AND mask; /x gives 232-x addresses, minus 2 usable. VLSM: largest first, aligned blocks. Aggregation needs contiguous aligned blocks.
  • Forwarding = longest-prefix match; default route 0.0.0.0/0.
  • DHCP: Discover, Offer, Request, ACK (UDP 67/68). NAT: port-number translation table, ~64k connections.
  • SDN: control plane separated; OpenFlow = match + action; P4 programs the data plane.
  • Dijkstra O(n2) (O(E log n) with heap); Bellman-Ford O(VE); DV: Dx(y) = min c(x,v)+Dv(y); count-to-infinity, poisoned reverse (two-node loops only).
  • RIP (UDP, hops, 15 max), OSPF (IP proto 89, link state, areas), BGP (TCP 179, path vector; LOCAL-PREF, AS-PATH, hot potato).
  • IPv6: 128-bit, 40-byte fixed header, no checksum, no router fragmentation, tunneling; multicast: IGMP + RPF + trees.
