Introduction & Application Layer

Weeks 1-5 · Kurose & Ross Ch. 1 (1.1-1.7) and Ch. 2 (2.1-2.7); Peterson-Davie Ch. 1, 9; Tanenbaum Ch. 1, 7

1. Computer networks and the Internet (K&R 1.1)

Definition. The Internet is a network of networks: billions of hosts (end systems) connected by communication links (fiber, copper, radio) and packet switches (routers, link-layer switches). A protocol defines the format and order of messages exchanged and the actions taken on sending or receiving a message.
  • Nuts and bolts view: hosts, links, packet switches, ISPs, protocols (TCP, IP, HTTP, 802.11), standards (IETF RFCs, IEEE).
  • Services view: infrastructure providing services to distributed applications through a socket interface.

2. The network edge (K&R 1.2)

The edge contains hosts (clients and servers) and the access networks that connect them to the first router (edge router).

Physical media: guided (twisted pair, coax, fiber) versus unguided (terrestrial radio, satellite). Fiber has very low attenuation and high capacity; radio suffers from fading, interference and multipath.

3. The network core (K&R 1.3)

3.1 Packet switching

Store-and-forward: a router must receive an entire packet before it begins to transmit the first bit onto the outgoing link. Over N links in series, each of rate R, a packet of L bits takes N·L/R (ignoring propagation and queueing).

Queueing and loss: if the arrival rate exceeds the output rate, packets queue in the output buffer; if the buffer is full they are dropped.

Forwarding vs routing: forwarding is the local action of moving a packet from input to output link using a forwarding table; routing is the global process of determining the end-to-end path and filling the tables.

3.2 Circuit switching

Resources (bandwidth slices) are reserved for the duration of the call, by frequency-division (FDM) or time-division multiplexing (TDM). Guaranteed performance but idle capacity is wasted. Example: a TDM link of 1.536 Mbps with 24 slots gives 64 kbps per call.

3.3 Packet vs circuit switching: statistical multiplexing

Worked example: a 1 Mbps link, users sending 100 kbps when active, active 10% of the time. Circuit switching supports 10 users. With packet switching and 35 users, the number of active users is Binomial(35, 0.1) and the probability that more than 10 are active is P(X > 10) = Σ C(35,k)(0.1)^k(0.9)^(35-k) for k = 11..35 ≈ 0.000424 (0.04%). Mean number active is 3.5, so packet switching supports more than 3x the users with only brief queueing.

P(X > 10) for n=35, p=0.1:
  = sum_{k=11}^{35} C(35,k) * 0.1^k * 0.9^(35-k)  ~= 4.2e-4
Pitfall. Packet switching is "great for bursty data" but gives no guarantees for constant-rate traffic such as voice without extra mechanisms; it does not eliminate queueing, it creates it.

3.4 Network of networks

Access ISPs connect to regional ISPs and Tier-1 ISPs, interconnected via peering links and IXPs; content providers (Google etc.) run private networks and CDNs to bring content close to users. Resulting structure is a multi-tier, partially flat hierarchy.

4. Delay, loss and throughput (K&R 1.4)

4.1 Four sources of delay

dnodal = dproc + dqueue + dtrans + dprop
dtrans = L/R (packet length in bits / link rate in bps)
dprop = d/s (link length / propagation speed, about 2 x 108 m/s in cable and fiber, 3 x 108 in air)
DelayDepends onTypical size
ProcessingHeader check, lookupmicroseconds
QueueingCongestion, variableµs to ms
TransmissionL and R onlyµs to ms
PropagationDistance and medium onlyµs to 100s of ms

Worked example. L = 1000 bytes = 8000 bits, R = 1 Mbps, 2500 km at 2.5 x 108 m/s: dtrans = 8 ms, dprop = 10 ms, so the last bit arrives 18 ms after the sender starts transmitting. Bits "in flight" on the link when transmission ends = R·dprop = 106 x 0.01 = 10,000 bits (the delay-bandwidth product).

Example (segmentation). A 7.5 Mbit message over 2 links of 1.5 Mbps: as one packet, 5 s per link gives 10 s. In 5000 packets of 1500 bits, each takes 1 ms per link and the links pipeline: (5000 + 1) x 1 ms = 5.001 s.

4.2 Queueing delay and traffic intensity

Let a be the average arrival rate (packets/s), L packet size, R link rate. Traffic intensity ρ = La/R. If ρ ≈ 0 delay is small; as ρ → 1 the average delay grows rapidly; ρ > 1 gives unbounded growth (loss with finite buffers). Design rule: keep ρ well below 1.

4.3 Loss, end-to-end delay, traceroute

Total end-to-end delay = sum of nodal delays over the N-1 routers on the path (plus transmission at the source). traceroute sends probes with increasing TTL; each router that drops the expired packet returns an ICMP message, giving a per-hop RTT estimate. Lost packets may be retransmitted by the previous node, the source, or not at all.

4.4 Throughput

Instantaneous throughput = rate at which the receiver gets bits; average = F/T. For a path of links with rates R1..Rn, the end-to-end throughput is min(Ri): the bottleneck link. When N connections share a common link of rate R with per-connection access rates Rs and Rc: throughput = min(Rs, Rc, R/N). Example: Rs = 2 Mbps, Rc = 1 Mbps, R = 5 Mbps, N = 10: min(2, 1, 0.5) = 0.5 Mbps.

Encapsulation: each layer adds its header to the payload from above (message → segment → datagram → frame); routers examine only the layers up to the network layer, link-layer switches only up to the link layer. The OSI model adds presentation and session layers, which the Internet leaves to applications. The end-to-end principle places reliability and similar functions in end hosts.

Idea. Layering gives modularity: each layer can change implementation without affecting others; its cost is some duplicated functionality and hidden information.

6. Application layer: principles (K&R 2.1)

6.1 Architectures

  • Client-server: always-on server with a fixed IP; clients communicate only with the server (Web, mail). Scaling needs data centers.
  • Peer-to-peer (P2P): arbitrary end systems communicate directly; self-scalability but harder to manage (BitTorrent, Skype-style systems).

A process communicates through a socket; it is identified by IP address plus port number. The application chooses a transport service by requirements: data integrity, throughput, timing, security. TCP offers reliable, in-order byte streams with flow and congestion control (no timing or throughput guarantees); UDP offers an unreliable datagram service with no set-up.

6.2 P2P file distribution: scalability

Client-server: Dcs = max(N·F/us, F/dmin)
P2P: Dp2p = max(F/us, F/dmin, N·F/(us + Σui))

Worked example: F = 10 Gbit, N = 10, us = 30 Mbps, each u = 2 Mbps, dmin = 10 Mbps. Dcs = max(3333.3, 1000) = 3333 s. Dp2p = max(333.3, 1000, 100000/50 = 2000) = 2000 s. As N grows Dcs grows linearly while Dp2p saturates, since every peer adds upload capacity.

BitTorrent: a torrent of peers exchanging 256 KB chunks; a tracker lists peers. A peer requests the rarest chunks first and sends data to the four peers currently sending it data at the highest rate (tit-for-tat / choking), plus one randomly chosen peer (optimistic unchoke).

DHT (distributed hash table): (key, value) pairs are spread over peers; a key is stored at the peer with the ID closest to the key (e.g. closest successor). With peers 1, 3, 4, 5, 8, 10, 12, 14: key 13 → peer 14; key 15 → wraps to peer 1. A circular DHT with shortcuts reduces lookup to O(log N) messages.

7. The Web and HTTP (K&R 2.2)

A web page has a base HTML file plus referenced objects, each addressed by a URL (host + path). HTTP is a client-server request/response protocol over TCP (port 80; HTTPS over TLS on port 443). It is stateless.

GET /dir/page.html HTTP/1.1
Host: www.example.edu
Connection: keep-alive
User-agent: Mozilla/5.0
Accept-language: en

HTTP/1.1 200 OK
Date: ...
Content-Length: 6821
Content-Type: text/html

(data...)

Methods: GET, POST, HEAD, PUT, DELETE. Status codes: 200 OK, 301 Moved Permanently, 304 Not Modified, 400 Bad Request, 404 Not Found, 505 HTTP Version Not Supported.

7.1 Non-persistent vs persistent

Non-persistent: 2 RTT + transmission time per object (1 RTT to open TCP, 1 RTT for request/response). Persistent (HTTP/1.1 default): the connection remains open; without pipelining each object costs 1 RTT, with pipelining a single RTT can fetch all referenced objects. Browsers also open parallel connections.

Worked example. Base file + 5 objects, RTT = 50 ms, negligible transmission times:

ModeComputationTotal
Non-persistent, serial6 x 2 x 50600 ms
Persistent, no pipelining2 x 50 + 5 x 50350 ms
Persistent, pipelining2 x 50 + 1 x 50150 ms

HTTP/2 multiplexes prioritised streams in one TCP connection (reducing head-of-line blocking at the HTTP level); HTTP/3 runs over QUIC/UDP.

7.2 Cookies

Four components: Set-Cookie header in the response, Cookie header in later requests, a cookie file on the user's host, and a back-end database at the site. Used for authentication, shopping carts, recommendations, session state. Privacy concern: tracking, third-party cookies.

7.3 Web caching (proxy servers) and conditional GET

A cache serves requests locally if it has the object; otherwise it fetches from the origin. It reduces response time, institutional access-link traffic and origin load. Conditional GET: request with If-Modified-Since: <date>; server replies 304 Not Modified (no body) if unchanged.

Worked example (access link). Objects of 100,000 bits at 15 requests/s offer 1.5 Mbps over a 2 Mbps access link: ρ = 0.75 (delay already large). With a 40% hit rate, only 0.6 x 1.5 = 0.9 Mbps crosses the link: ρ = 0.45. Expected delay with hit time 10 ms and miss time 200 ms: 0.4 x 10 + 0.6 x 200 = 124 ms.

CDNs store copies of content in clusters near users; DNS redirection (or HTTP redirect) sends a client to a nearby cluster. Web 2.0/3.0: Web 2.0 is interactive, user-generated, AJAX/API-driven content; Web 3.0 refers to semantic and decentralised (blockchain-based, user-owned data) web proposals.

Pitfalls. HTTP being stateless does not mean the TCP connection is closed. A 304 response has no body. The persistent-connection RTT counts depend on whether pipelining is assumed.

8. DNS (K&R 2.4)

Idea. A distributed, hierarchical database mapping hostnames to IP addresses (plus aliasing, mail-server lookup and load distribution), running over UDP port 53.

Hierarchy: root servers → top-level domain (TLD) servers (.com, .edu, .in) → authoritative servers for organisations. A local DNS server (default resolver) is not strictly in the hierarchy and acts as a proxy for hosts.

resolve(name):                      # iterative, from local DNS server
    if name in cache: return cache[name]
    ns = root_server
    while ns is not authoritative for name:
        reply = query(ns, name)
        if reply has A record: break
        ns = reply.referral           # next-level server
    cache[name] = reply (with TTL)
    return reply

Iterative vs recursive: recursive – the queried server resolves on the client's behalf (heavier load at upper levels); iterative – the server returns a referral. Typically host→local server is recursive and the local server→hierarchy is iterative. Caching of results (TTL-based) means roots are rarely contacted.

TypeNameValue

Messages (query and reply) share one format: 16-bit identifier, flags, counts, then question, answer, authority and additional sections. Records are added through a registrar (e.g. NS and glue A record at the parent TLD). Attacks: DDoS on roots, cache poisoning, spoofing (mitigated by DNSSEC).

Worked example. Resolving www.nitc.ac.in with an empty cache: local server asks root (referral to .in TLD), asks the .in TLD (referral to the next level), then asks authoritative servers until an A record is returned: 4 iterative queries if ac.in and nitc.ac.in are separate delegations. With cached NS records only the last query is needed.

9. E-mail: SMTP, POP3, IMAP (K&R 2.3)

Components: user agents, mail servers (mailbox and outgoing message queue), SMTP. SMTP (TCP port 25) is a push protocol, uses persistent connections, requires 7-bit ASCII messages (MIME encodes binary data), and ends the body with a line holding only a period.

S: 250 Hello
C: MAIL FROM: <alice@alice.org>
S: 250 OK
C: RCPT TO: <bob@example.edu>
S: 250 OK
C: DATA
S: 354 End data with <CR><LF>.<CR><LF>
C: Subject: Hi ... body ...
C: .
S: 250 Message accepted
C: QUIT
S: 221 Bye

Pitfall. SMTP vs HTTP: SMTP pushes, HTTP pulls; SMTP puts all objects in one multi-part message while HTTP encapsulates each object in its own response.

10. Multimedia and streaming applications (K&R 2.6, Ch. 9 ideas)

  • Audio/video basics: sampling and quantisation (e.g. 8000 samples/s x 8 bits = 64 kbps PCM); video as a sequence of images, compressed with spatial (within frame) and temporal (between frames) redundancy; CBR vs VBR coding.
  • Streaming stored video: UDP streaming (constant rate, loss and firewall problems), HTTP/TCP streaming with client buffering and playout delay, and DASH: video divided into chunks encoded at several bitrates; a manifest file lists the URLs; the client chooses the bitrate per chunk based on measured throughput and buffer.
  • Voice-over-IP: delay-sensitive, loss-tolerant; tolerable end-to-end delay below about 150 ms (400 ms upper limit); adaptive playout and forward error correction or interleaving to handle jitter and loss. Real-time protocols: RTP over UDP, SIP for signalling.
  • CDNs (Netflix, YouTube) place chunks in clusters near users, often inside ISPs (enter-deep) or at IXPs (bring-home).

Worked example (playout buffer). If a video arrives at rate r and plays at rate p < r, the buffer fills at r - p; start-up delay (initial buffering) hides jitter. If r < p the buffer empties and playback stalls (freezing).

11. Socket programming (K&R 2.7)

11.1 UDP (connectionless)

# client
s = socket(AF_INET, SOCK_DGRAM)
s.sendto(msg, (server_name, 12000))
reply, addr = s.recvfrom(2048)

# server
s = socket(AF_INET, SOCK_DGRAM); s.bind(('', 12000))
while True:
    msg, client_addr = s.recvfrom(2048)
    s.sendto(msg.upper(), client_addr)

11.2 TCP (connection-oriented)

# server
w = socket(AF_INET, SOCK_STREAM); w.bind(('', 12000)); w.listen(1)
while True:
    conn, addr = w.accept()        # new socket per client
    data = conn.recv(1024)
    conn.send(data.upper())
    conn.close()

# client
s = socket(AF_INET, SOCK_STREAM)
s.connect((server_name, 12000))    # three-way handshake
s.send(msg); reply = s.recv(1024); s.close()

Key differences: UDP has no handshake, each datagram carries the destination, the server uses a single socket for all clients, data may be lost or reordered. TCP requires the server to run before clients connect, uses a welcoming socket plus a connection socket per client, and offers a reliable byte stream (no message boundaries, so applications must frame messages).

Pitfalls. A TCP recv may return fewer bytes than the sender wrote in one send. A UDP server must remember the client address from recvfrom to reply. Forgetting to close sockets leaks resources.

Quick revision

  • Edge = hosts + access networks; core = packet switches and links; packet switching uses statistical multiplexing and store-and-forward (N·L/R over N links).
  • dnodal = proc + queue + trans (L/R) + prop (d/s); only queueing varies; ρ = La/R must stay below 1.
  • Throughput = min of link rates (bottleneck); shared link gives R/N.
  • Five layers: application, transport, network, link, physical; encapsulation adds headers; end-to-end principle.
  • D_cs = max(NF/u_s, F/d_min); D_p2p = max(F/u_s, F/d_min, NF/(u_s + Σu)); BitTorrent: rarest first, tit-for-tat; DHT: closest successor.
  • HTTP stateless over TCP; non-persistent 2 RTT per object; persistent with pipelining about 1 RTT for all objects; cookies add state.
  • Caching: conditional GET with 304; expected delay = hit·d_hit + miss·d_miss; hit rate cuts access-link utilisation.
  • DNS: hierarchy root/TLD/authoritative, UDP port 53, caching with TTL; records A, AAAA, NS, CNAME, MX; iterative vs recursive.
  • SMTP pushes (HELO, MAIL FROM, RCPT TO, DATA, ".", QUIT); POP3 downloads; IMAP manages mail on the server.
  • Streaming: DASH chunks at multiple bitrates chosen by the client; VoIP delay under about 150 ms; playout buffer hides jitter.
  • Sockets: UDP uses sendto/recvfrom; TCP uses listen/accept/connect and a per-client connection socket.
