T1 — Algorithmic Foundations and Divide & Conquer

Binary search, recursion, D&C, sorting bounds, selection, exponentiation, matrix multiplication, maximum subarray, inversions, closest pair. Refs: CLRS Ch.2–4, 7, 8, 9; DPV Ch.2; Kleinberg–Tardos Ch.5; Levitin Ch.4–5.

1. Recursion and recurrences (foundation)

Recursive problem solving. Express the answer for input of size n using answers for smaller instances of the same problem, plus a base case. Correctness is proved by induction on the size; running time is a recurrence.

Divide and Conquer (D&C): (1) Divide into a subproblems of size n/b; (2) Conquer recursively; (3) Combine in f(n) time. So T(n) = a·T(n/b) + f(n).

Solving recurrences

  • Recursion tree: level i has a^i nodes each of cost f(n/b^i); sum the levels (depth log_b n).
  • Substitution: guess the form, prove by induction (check constants and the base case).
  • Master theorem (T(n)=aT(n/b)+Θ(n^d), a≥1, b>1): compare d with log_b a.
CaseConditionResult
Leaves dominated < log_b aΘ(n^(log_b a))
Balancedd = log_b aΘ(n^d log n)
Root dominatesd > log_b aΘ(n^d)

General form (CLRS): f(n) = Θ(n^(log_b a) · log^k n) gives Θ(n^(log_b a) · log^(k+1) n) for k ≥ 0.

Worked example. T(n)=3T(n/2)+n: log_2 3 ≈ 1.585 > 1, so T(n)=Θ(n^1.585). T(n)=2T(n/2)+n log n: Θ(n log² n) (k=1 case). T(n)=T(n-1)+n is not master-form: unrolling gives n(n+1)/2 = Θ(n²).

Pitfalls. Master theorem needs equal-size subproblems and polynomial gap between f(n) and n^(log_b a); T(n)=2T(n/2)+n/log n is not covered. Naive Fibonacci, T(n)=T(n-1)+T(n-2)+1, is Θ(φ^n), exponential, because subproblems overlap (motivation for DP).

2. Binary search and its variants

Idea. On a sorted array, compare with the middle element and discard half. Invariant: if the key exists, it lies in A[lo..hi].

BinarySearch(A, n, x):
  lo = 0; hi = n-1
  while lo <= hi:
    mid = lo + (hi - lo) / 2        // avoids overflow
    if A[mid] == x: return mid
    else if A[mid] < x: lo = mid + 1
    else: hi = mid - 1
  return -1

Complexity. T(n)=T(n/2)+Θ(1) ⇒ Θ(log n). Worst case comparisons (3-way) = ⌊log₂ n⌋ + 1; e.g. n=1000 needs 10 iterations.

Variants

LowerBound(A, n, x):   // first index i with A[i] >= x  (n if none)
  lo = 0; hi = n                  // search in [lo, hi)
  while lo < hi:
    mid = lo + (hi - lo) / 2
    if A[mid] < x: lo = mid + 1
    else: hi = mid
  return lo
// UpperBound: same with test A[mid] <= x  → first index with A[i] > x
// Count of x = UpperBound - LowerBound; first occurrence = LowerBound.

Example. A=[1,2,2,2,3,5], x=2: LowerBound=1, UpperBound=4, count=3.

  • Search in rotated sorted array: one half around mid is always sorted; decide if x is in it. Θ(log n) (distinct keys).
  • Peak finding / search on answer: binary search on a monotone predicate (e.g., smallest x with P(x) true), also used for square root, capacity problems.
  • Unbounded search: double the index (1,2,4,…) until A[i] ≥ x, then binary search: Θ(log p), p = position.
Pitfalls. Off-by-one with lo<=hi vs lo<hi; infinite loops if lo=mid instead of mid+1; (lo+hi) overflow; duplicates (plain search returns any occurrence).

3. Merge sort

Idea. Split in halves, sort each recursively, merge two sorted lists in linear time.

MergeSort(A, l, r):
  if l < r:
    m = (l + r) / 2
    MergeSort(A, l, m); MergeSort(A, m+1, r)
    Merge(A, l, m, r)

Merge: copy halves L, R; repeatedly move the smaller front element
       (take from L on ties for stability); append the leftover.

Correctness. Merge maintains: output so far holds the smallest elements in order; induction gives sortedness of MergeSort.

Complexity. T(n)=2T(n/2)+Θ(n) ⇒ Θ(n log n) in all cases. Merging lists of sizes p and q takes at most p+q−1 comparisons; worst-case total comparisons for n=2^k is n log₂n − n + 1 (n=8: 17). Space Θ(n), stable, not in-place. Recursion tree: log₂n + 1 levels, each doing n work.

Example. [38,27,43,3] → [38,27],[43,3] → [27,38],[3,43] → merge: 3,27,38,43.

4. Lower bound for comparison-based sorting

Theorem. Any comparison sort needs Ω(n log n) comparisons in the worst case.

Proof (decision tree). A deterministic comparison sort is a binary tree: internal nodes are comparisons a_i : a_j, leaves are output permutations. To be correct every one of the n! permutations must appear as a leaf. A binary tree of height h has ≤ 2^h leaves, so 2^h ≥ n! ⇒ h ≥ log₂(n!) = Θ(n log n) (since n! ≥ (n/2)^(n/2), or Stirling). Numbers: n=5 needs ≥ ⌈log₂120⌉ = 7 comparisons; n=8 needs ≥ ⌈log₂40320⌉ = 16.

Hence merge sort and heap sort are asymptotically optimal. The average case is also Ω(n log n) (average leaf depth ≥ log₂ n!).

Pitfall. The bound applies only to comparison models. Counting sort (O(n+k)), radix sort, bucket sort beat it by using key values/indexing, not comparisons.

5. Quicksort

Idea. Pick a pivot, partition so that smaller elements are left and larger right, recurse on both sides. Work is done in the divide step; combine is free.

Partition(A, l, r):         // Lomuto, pivot = A[r]
  p = A[r]; i = l - 1
  for j = l to r-1:
    if A[j] <= p: i++; swap A[i], A[j]
  swap A[i+1], A[r]
  return i+1

Quicksort(A, l, r):
  if l < r: q = Partition(A, l, r); Quicksort(A, l, q-1); Quicksort(A, q+1, r)

Trace. A=[7,2,9,4,3,8,5], pivot 5: scanning moves 2,4,3 to the left block; result [2,4,3,5,9,8,7], pivot index 3.

Analysis

  • Worst case: unbalanced split (sorted input with last-element pivot): T(n)=T(n-1)+Θ(n) ⇒ Θ(n²); n(n−1)/2 comparisons (n=10: 45).
  • Best case: T(n)=2T(n/2)+Θ(n) ⇒ Θ(n log n). Even a constant-fraction split (e.g. 9:1) gives Θ(n log n).
  • Randomized quicksort (random pivot): expected comparisons ≈ 2n ln n ≈ 1.39 n log₂n. Proof via indicator variables: elements of ranks i<j are compared iff one of them is the first pivot chosen among ranks i..j, so Pr = 2/(j−i+1); E[comparisons] = Σ_{i<j} 2/(j−i+1) = O(n log n) (harmonic sum). E.g. ranks 3 and 7: 2/5.

In-place (O(log n) expected stack), not stable, fast in practice due to cache behaviour. Handle duplicates with 3-way partition (Dutch flag).

Pitfall. Deterministic first/last pivot is Θ(n²) on sorted/reverse input; use random pivot or median-of-three.

6. Quickselect and expected running time

Problem. Find the k-th smallest of n elements without full sorting.

Select(A, l, r, k):         // k-th smallest in A[l..r], 1-based
  q = RandomizedPartition(A, l, r)
  rank = q - l + 1
  if k == rank: return A[q]
  if k < rank: return Select(A, l, q-1, k)
  else: return Select(A, q+1, r, k - rank)

Expected time Θ(n). Call a pivot good if it lies in the middle half (probability 1/2); a good pivot leaves ≤ 3n/4 elements. Expected 2 partitions per good step, so E[T(n)] ≤ E[T(3n/4)] + 2·cn ⇒ geometric series ≤ 8cn = O(n). Worst case Θ(n²).

Example. k=3 in [7,2,9,4,3,8,5]: after partition pivot 5 at rank 4; 3 < 4 ⇒ recurse on [2,4,3] with k=3 ⇒ answer 4.

7. Median finding in worst-case linear time (median of medians)

MoM-Select(A, k):
  1. split into ⌈n/5⌉ groups of 5; sort each; take group medians
  2. m = MoM-Select(medians, ⌈n/10⌉)      // median of medians
  3. partition A around m
  4. recurse into the side containing the k-th element

Why it works. At least about 3n/10 − 6 elements are ≤ m and as many ≥ m, so each recursion side has ≤ 7n/10 + 6 elements. T(n) ≤ T(n/5) + T(7n/10 + 6) + cn. Since 1/5 + 7/10 = 9/10 < 1, T(n)=O(n) (substitution T(n) ≤ 10cn).

Pitfall. Groups of 3 give T(n)=T(n/3)+T(2n/3)+cn = Θ(n log n): 1/3+2/3 = 1 breaks linearity. Groups of 7 also work. The constant is large, so randomized quickselect is used in practice. Using it as the quicksort pivot gives worst-case O(n log n) quicksort.

8. Fast exponentiation

Idea. a^n = (a^(n/2))² if n even, a·(a^((n-1)/2))² if odd. Compute the half power once.

Power(a, n):
  if n == 0: return 1
  h = Power(a, n / 2)             // floor
  if n even: return h * h
  else: return h * h * a

Complexity. T(n)=T(n/2)+Θ(1) ⇒ Θ(log n) multiplications (between ⌊log₂n⌋ and 2⌊log₂n⌋) versus n−1 naively. Example: 3^13, 13=1101₂ ⇒ 3, 3², 3³, 3⁶, 3¹², 3¹³ = 5 multiplications, value 1594323; 2^15 takes 6; 5^10 takes 4. With modulus M, reduce after each multiplication (modular exponentiation, used in RSA); also computes Fibonacci F(n) via the matrix [[1,1],[1,0]]^n in Θ(log n) matrix products.

Pitfall. Writing Power(a,n/2)*Power(a,n/2) makes two calls: T(n)=2T(n/2)+1 = Θ(n), no gain. Mind overflow and bit-cost of big numbers.

9. Matrix multiplication (naive D&C and Strassen)

Naive: Θ(n³) (three loops). Block D&C: split each n×n matrix into four n/2 blocks; C11=A11B11+A12B21 etc. takes 8 half-size products + Θ(n²) additions: T(n)=8T(n/2)+Θ(n²) = Θ(n³), no gain.

Strassen (1969). Compute 7 products: M1=(A11+A22)(B11+B22), M2=(A21+A22)B11, M3=A11(B12−B22), M4=A22(B21−B11), M5=(A11+A12)B22, M6=(A21−A11)(B11+B12), M7=(A12−A22)(B21+B22). Then C11=M1+M4−M5+M7, C12=M3+M5, C21=M2+M4, C22=M1−M2+M3+M6.

T(n)=7T(n/2)+Θ(n²) ⇒ Θ(n^(log₂7)) ≈ Θ(n^2.807). Assumes n a power of 2 (pad with zeros). Example: for n=1024 with scalar base case, Strassen uses 7^10 = 282,475,249 scalar multiplications versus 8^10 = 1,073,741,824 for the naive scheme. Large hidden constant and weaker numerical stability: it pays off only for large n (hundreds+). Same trick in integer multiplication (Karatsuba): T(n)=3T(n/2)+n = Θ(n^1.585).

10. Maximum subarray problem

Problem. Given A[1..n] of reals, find a contiguous subarray with maximum sum.

MaxSub(A, l, r):
  if l == r: return A[l]
  m = (l + r) / 2
  left  = MaxSub(A, l, m); right = MaxSub(A, m+1, r)
  cross = (best sum of a suffix ending at m) + (best sum of a prefix starting at m+1)
  return max(left, right, cross)

Cross sum is found in Θ(n) by scanning outwards from m. T(n)=2T(n/2)+Θ(n) = Θ(n log n). (Brute force Θ(n²) with prefix sums; Kadane gives Θ(n): cur = max(A[i], cur + A[i]), best = max(best, cur).)

Example. A=[−2,1,−3,4,−1,2,1,−5,4]: answer 6 for [4,−1,2,1].

Pitfall. Forgetting the crossing case; the cross part must contain both A[m] and A[m+1]. If all elements are negative the answer is the single largest element (non-empty subarray convention).

11. Counting inversions

Definition. An inversion is a pair i<j with A[i] > A[j]; it measures how far the array is from sorted (0 for sorted, n(n−1)/2 for reverse). Used for ranking similarity.

Algorithm. Piggyback on merge sort: count = inv(left) + inv(right) + cross. During merge, when an element of the right half is placed before remaining elements of the left half, add the number of remaining left elements.

SortCount(A):
  if |A| <= 1: return (A, 0)
  (L, a) = SortCount(left half); (R, b) = SortCount(right half)
  merge L, R; whenever R[j] is output while L has t elements left: c += t
  return (merged, a + b + c)

T(n)=2T(n/2)+Θ(n)=Θ(n log n) versus Θ(n²) brute force. Example. [5,3,2,4,1]: inversions = (5,3),(5,2),(5,4),(5,1),(3,2),(3,1),(2,1),(4,1) = 8.

Pitfall. Count cross inversions only while the halves are sorted; if the halves are not sorted the merge trick fails. Use strict > (equal keys are not inversions).

12. Closest pair of points

Problem. Among n points in the plane find two at minimum Euclidean distance. Brute force Θ(n²).

Closest(P):                // P sorted by x; also keep list sorted by y
  if |P| <= 3: brute force
  split at median x-coordinate (line L) into Pl, Pr
  d = min(Closest(Pl), Closest(Pr))
  S = points within distance d of L, ordered by y
  for each point in S: compare with the next 7 points in S   // strip check
  return min(d, best found)

Why the strip step is O(n). In the strip, a d × 2d rectangle holds at most 8 points (each d/2 × d/2 cell contains ≤ 1 point because pairs on one side are ≥ d apart), so each point needs checking against ≤ 7 successors in y-order. Keeping y-order via merging (not re-sorting) gives T(n)=2T(n/2)+Θ(n)=Θ(n log n); re-sorting the strip each time gives Θ(n log² n).

Pitfalls. The strip can contain nearly all points, so it is not small in the worst case; the constant-neighbours argument is what bounds it. Points on the dividing line and duplicate x-values need consistent tie-breaking.

Quick revision

  • D&C: divide, conquer, combine; T(n)=aT(n/b)+n^d; compare d with log_b a.
  • Binary search Θ(log n), ⌊log₂n⌋+1 comparisons; lower/upper bound variants use half-open [lo,hi).
  • Merge sort Θ(n log n) always, stable, Θ(n) extra space.
  • Comparison sort lower bound: log₂(n!) = Ω(n log n) from n! leaves in decision tree.
  • Quicksort: worst Θ(n²), expected ≈ 2n ln n; Pr[ranks i,j compared] = 2/(j−i+1).
  • Quickselect expected Θ(n), worst Θ(n²); median of medians (groups of 5) worst-case Θ(n).
  • Fast exponentiation Θ(log n) multiplications; compute the half power once.
  • Strassen: 7 multiplications, Θ(n^2.807); Karatsuba: 3 multiplications, Θ(n^1.585).
  • Max subarray D&C Θ(n log n) (cross case!), Kadane Θ(n).
  • Inversions via merge sort; closest pair via strip with ≤ 7 neighbours; both Θ(n log n).
