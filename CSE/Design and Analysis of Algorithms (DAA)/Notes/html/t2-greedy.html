T2 — Greedy Algorithms

Greedy paradigm, Maximum Independent Set in trees, Interval Scheduling, Fractional Knapsack, Minimum Spanning Trees, Huffman Coding. Ref: DPV Ch.5; CLRS 4e Ch.15 and Ch.21; KT Ch.4; Erickson Ch.4.

1. The greedy strategy and design paradigm

Idea. Build a solution piece by piece; at each step make the choice that looks best right now (locally optimal) and never undo it. The result is globally optimal only for problems with special structure.

Two properties justify a greedy algorithm:

  • Greedy-choice property: some optimal solution contains the greedy first choice.
  • Optimal substructure: after making that choice, the rest of the problem is a smaller instance of the same problem, whose optimal solution combines with the choice to give an optimal whole.

Proof techniques

  • Exchange argument: take any optimal solution O. Show you can swap one of its elements for the greedy choice without making it worse. Repeat until O equals the greedy solution.
  • Greedy stays ahead: show by induction that after k steps the greedy partial solution is at least as good as any other partial solution of k steps.
  • Cut / structural argument (used for MSTs).

Typical template

Greedy(input):
    sort candidates by a well-chosen key            // often O(n log n)
    solution = empty
    for each candidate c in that order:
        if c is feasible with solution:
            add c to solution
    return solution
Pitfall. A plausible greedy rule is not a proof. Always test against a counterexample (e.g. coin change with {1,3,4}, target 6: greedy gives 4+1+1 = 3 coins, optimum is 3+3 = 2 coins). Greedy differs from DP: it does not try all subproblem choices and never has overlapping subproblems to tabulate.

2. Interval scheduling

Problem. Given n requests with start si and finish fi, choose a maximum-size subset of pairwise compatible (non-overlapping) intervals. Intervals sharing only an endpoint are compatible.

Algorithm: earliest finish time first

IntervalSchedule(s[1..n], f[1..n]):
    sort intervals so that f[1] <= f[2] <= ... <= f[n]
    A = {1};  last = f[1]
    for i = 2 to n:
        if s[i] >= last:
            A = A + {i};  last = f[i]
    return A

Why other rules fail

RuleCounterexample
Earliest start(0,10),(1,2),(3,4),(5,6): picks 1, optimum 3
Shortest interval(0,5),(4,6),(5,10): picks (4,6), optimum 2 ((0,5),(5,10))
Fewest conflictsKnown counterexamples with 11 intervals

Correctness (greedy stays ahead)

Let greedy pick i1,...,ik and an optimal solution pick j1,...,jm, both ordered by time. Claim: f(ir) ≤ f(jr) for all r. Base: i1 has the globally smallest finish. Step: jr+1 starts after f(jr) ≥ f(ir), so it is a candidate when greedy picks ir+1, hence f(ir+1) ≤ f(jr+1). If m > k, jk+1 would still be compatible with greedy's last interval, a contradiction; so k ≥ m.

Worked example

Intervals (1,4),(3,5),(0,6),(5,7),(3,9),(5,9),(6,10),(8,11),(8,12),(2,14),(12,16). Sorted by finish: (1,4),(3,5),(0,6),(5,7),(3,9),(5,9),(6,10),(8,11),(8,12),(2,14),(12,16). Pick (1,4); skip (3,5),(0,6); pick (5,7); skip (3,9),(5,9),(6,10); pick (8,11); skip (8,12),(2,14); pick (12,16). Answer: 4 intervals. (Earliest start would pick (0,6),(6,10),(12,16) = only 3.)

Complexity: O(n log n) for sorting + O(n) scan = O(n log n).

3. Fractional knapsack

Problem. Items i with value vi and weight wi; capacity W. Any fraction xi ∈ [0,1] of an item may be taken. Maximise Σ xivi subject to Σ xiwi ≤ W.

FractionalKnapsack(v, w, W):
    sort items by v[i]/w[i] in decreasing order
    remaining = W;  total = 0
    for each item i in that order:
        if w[i] <= remaining:
            take all: total += v[i];  remaining -= w[i]
        else:
            total += v[i] * remaining / w[i]     // fraction
            break
    return total

Correctness (exchange). Suppose an optimal solution uses a unit of capacity on item j while a strictly denser item i is not used up. Replacing that unit of j by a unit of i raises the value, a contradiction. Hence all of the densest items must be fully used before any less dense one.

Example. (value,weight) = (60,10),(100,20),(120,30), W = 50. Ratios 6, 5, 4. Take items 1 and 2 (weight 30, value 160), then 20/30 of item 3 = 80. Total 240.

Complexity: O(n log n) (sorting); O(n) is possible with weighted-median selection.
Pitfall. The same ratio rule is NOT optimal for 0/1 knapsack: for the items above with W = 50 greedy gives 160 (items 1 and 2) but the optimum is 220 (items 2 and 3). 0/1 knapsack needs DP (Topic 3).

4. Maximum Independent Set in trees

Definition. An independent set is a set of vertices with no two adjacent. Finding a maximum one is NP-hard in general graphs, but easy for trees (and forests).

TreeMIS(T):
    S = empty
    while T has vertices:
        pick a leaf u (degree <= 1; isolated vertices count)
        S = S + {u}
        remove u and its neighbour (if any) from T   // forest may split
    return S

Correctness (exchange). Let ℓ be a leaf with neighbour p. If an optimal set O omits ℓ, then p ∈ O (else add ℓ, contradicting optimality). O − {p} + {ℓ} is still independent (ℓ's only neighbour is p) and has the same size. So some optimal set contains ℓ; remaining problem is the forest T − {ℓ, p}.

Example. Edges 1-2, 1-3, 1-4, 2-5, 2-6, 4-7. Leaves: 3,5,6,7. Pick 5 (delete 2); pick 6; pick 3 (delete 1); pick 7 (delete 4). S = {3,5,6,7}, size 4, which is optimal.

Complexity: O(n) with degree counters / a queue of leaves (each vertex removed once). A DP alternative: for each vertex store best with and without it.
Pitfall. Picking a high-degree or internal vertex is not safe. The argument needs a degree-1 vertex; a general graph (e.g. a cycle) may have none, which is why this fails there.

5. Minimum Spanning Tree (MST)

Problem. Connected undirected weighted graph G = (V,E). A spanning tree is an acyclic connected subgraph on all V (exactly |V|−1 edges). Find one with minimum total weight.

Key properties

Cut property. For any cut (S, V−S), a minimum-weight edge crossing the cut belongs to some MST (to every MST if it is the unique lightest).
Cycle property. A strictly heaviest edge on any cycle belongs to no MST.
If all weights are distinct, the MST is unique.

Proof of the cut property (exchange). Let T be an MST and e the lightest edge across the cut, e ∉ T. Adding e to T creates a cycle, which must cross the cut again at some other edge e′. Then T − e′ + e is a spanning tree with weight ≤ that of T, so it is also an MST containing e.

Kruskal's algorithm

Kruskal(G):
    A = empty;  make-set(v) for every vertex v
    sort edges by weight
    for each edge (u,v) in sorted order:
        if find(u) != find(v):
            A = A + {(u,v)};  union(u,v)
    return A

Union–find (disjoint sets) with union by rank and path compression gives near-constant amortised O(α(V)) per operation.

Complexity: sort O(E log E) = O(E log V); E find/union calls O(E α(V)). Total O(E log V).

Prim's algorithm

Prim(G, r):
    for each v: key[v] = infinity, parent[v] = nil
    key[r] = 0;  Q = priority queue of all vertices keyed by key
    while Q not empty:
        u = extract-min(Q)
        for each neighbour v of u:
            if v in Q and w(u,v) < key[v]:
                key[v] = w(u,v);  parent[v] = u    // decrease-key
ImplementationTime
Array / adjacency matrixO(V²) (good for dense graphs)
Binary heapO(E log V)
Fibonacci heapO(E + V log V)

Worked example (both algorithms)

Edges: A-B 4, A-C 2, B-C 1, B-D 5, C-D 8, C-E 10, D-E 2, D-F 6, E-F 3.

Kruskal: sorted order B-C 1 (take), A-C 2 (take), D-E 2 (take), E-F 3 (take), A-B 4 (reject, cycle A-B-C), B-D 5 (take, joins the two components). 5 edges, weight 13.

Prim from A: A-C 2 → C; B-C 1 → B; B-D 5 → D; D-E 2 → E; E-F 3 → F. Order A,C,B,D,E,F, weight 13. Same tree, as expected (all other edges are heavier on their cycles).

Pitfalls. Prim picks the lightest edge leaving the current tree (not the lightest overall edge). Kruskal must check cycles; adding an edge within a component is wrong. Dijkstra is NOT Prim: Dijkstra compares key = dist[u] + w, Prim just w. MST is unchanged by monotone transformations of weights (e.g. squaring positive weights) but shortest paths are not.

6. Huffman coding

Problem. Given symbols with frequencies f(c), find a binary prefix code (no codeword is a prefix of another, so decoding is unambiguous) minimising the total length B = Σ f(c)·depth(c). Such a code corresponds to a full binary tree with symbols at leaves; left edge = 0, right edge = 1.

Huffman(C):                       // C = set of n symbols with frequencies
    Q = min-priority queue of C by frequency
    for i = 1 to n-1:
        x = extract-min(Q);  y = extract-min(Q)
        z = new node with f(z) = f(x) + f(y), left = x, right = y
        insert(Q, z)
    return extract-min(Q)         // root of the code tree

Correctness. (1) Greedy choice: there is an optimal tree where the two least frequent symbols x,y are siblings at the deepest level (swap argument: moving a more frequent symbol deeper than a less frequent one never helps). (2) Optimal substructure: merging x,y into z with f(z) = f(x)+f(y) reduces cost by exactly f(x)+f(y), so an optimal tree for the reduced alphabet extends to an optimal tree for the original.

Worked example

a:5, b:9, c:12, d:13, e:16, f:45.

StepMergeNew node
1a(5) + b(9)14
2c(12) + d(13)25
314 + e(16)30
425 + 3055
5f(45) + 55100

Code lengths: f=1; c,d,e=3; a,b=4. Cost = 45·1 + (12+13+16)·3 + (5+9)·4 = 45 + 123 + 56 = 224 (equals the sum of internal node weights 14+25+30+55+100). A fixed-length 3-bit code costs 300.

Complexity: n−1 merges, each O(log n) with a binary heap: O(n log n) (O(n) if frequencies are pre-sorted, using two queues). Tree has n leaves and n−1 internal nodes.
Pitfalls. Ties give different but equally optimal codes. Huffman gives the best symbol-by-symbol prefix code, not the best compressor overall (e.g. no benefit from repeated patterns). Skewed (Fibonacci-like) frequencies produce a chain of depth n−1.

7. Choosing a technique

Clue in the problemLikely technique
Sort + one scan; exchange argument worksGreedy
Items may be splitGreedy (fractional)
Items all-or-nothing, weights arbitraryDP (0/1 knapsack), greedy fails
Connect all vertices at minimum costMST (Prim / Kruskal)
Variable-length prefix-free codeHuffman
Choices interact in many ways, greedy counterexample existsDP or search

Quick revision

  • Greedy = locally best, never reconsider; needs greedy-choice property + optimal substructure; prove by exchange or stays-ahead.
  • Interval scheduling: sort by finish time, take if start ≥ last finish. O(n log n). Earliest start and shortest-first are wrong.
  • Fractional knapsack: sort by v/w descending, split the last item. O(n log n). Greedy fails for 0/1.
  • Tree MIS: repeatedly take a leaf, delete it and its neighbour. O(n). NP-hard on general graphs.
  • MST: cut property (lightest crossing edge is safe), cycle property (heaviest cycle edge is out); MST has V−1 edges; unique if weights distinct.
  • Kruskal: sort edges + union–find, O(E log V). Prim: grow a tree with a heap, O(E log V) (O(V²) with array, O(E + V log V) with Fibonacci heap).
  • Huffman: repeatedly merge two least frequent nodes; n−1 merges; O(n log n); cost = sum of internal node weights; Fibonacci frequencies give depth n−1.
  • Counterexample habit: coin change {1,3,4} for 6; 0/1 knapsack ratio greedy.
