T4 — NP-Completeness, Approximation and Heuristics

CS3003E DAA · Refs: DPV Ch.8, CLRS Ch.34–35, Kleinberg–Tardos Ch.8, Levitin Ch.11–12

1. Decision problems and polynomial-time reductions

Decision problem: a yes/no question about an input, e.g. "does graph G have a clique of size ≥ k?". Optimisation problems are converted to decision form by adding a threshold (k). Complexity theory studies decision problems because they are cleanly formalised as languages (sets of "yes" strings), and the optimisation version is never easier than the decision version (if you can optimise, you can decide).

Input size is measured in bits. An algorithm is polynomial if it runs in O(nc) for input length n. Beware pseudo-polynomial times such as O(nW) for knapsack, which is exponential in the bit-length of W.

Reductions

A polynomial-time (Karp) reduction A ≤p B is a function f computable in polynomial time such that for every input x: x ∈ A ⇔ f(x) ∈ B. Meaning: "B is at least as hard as A". If B ∈ P then A ∈ P; contrapositively, if A is hard then B is hard.
Direction pitfall. To prove a new problem X is hard, reduce a KNOWN hard problem TO X (known ≤p X). Reducing X to a known problem proves nothing about hardness. A correct reduction must preserve BOTH directions (yes→yes and no→no) and be computable in polynomial time (in particular the output size is polynomial).

Reductions are transitive: A ≤p B and B ≤p C give A ≤p C (compose two polynomials). This is what makes chains of reductions work.

2. Classes P, NP, NP-hard, NP-complete

ClassDefinitionExample
PDecidable in polynomial timeShortest path, MST, 2-SAT, matching
NPYes-instances have a certificate checkable in polynomial time (equivalently, decidable by a nondeterministic poly-time machine)SAT, Clique, Hamiltonian cycle, Subset Sum
NP-hardEvery problem in NP reduces to it (need not be in NP)Halting problem; optimisation TSP
NP-completeIn NP and NP-hard3-SAT, Vertex Cover, ...

Certificate/verifier idea: for Clique the certificate is the k vertices; the verifier checks that all C(k,2) pairs are edges in O(k²). P ⊆ NP (the verifier just solves the problem). Whether P = NP is open; if any NP-complete problem is in P then P = NP.

Recipe to prove X is NP-complete: (1) show X ∈ NP by giving a poly-time verifier; (2) pick a known NP-complete Y and give a poly-time f with y ∈ Y ⇔ f(y) ∈ X; (3) prove correctness in both directions and the polynomial running time of f.

co-NP: complements of NP problems (certificate for "no"). P ⊆ NP ∩ co-NP; it is believed that NP ≠ co-NP.

3. SAT and the Cook–Levin theorem

SAT: given a Boolean formula in CNF (AND of clauses, each an OR of literals), is there a truth assignment making it true? 3-SAT: every clause has exactly 3 literals. 2-SAT is in P (implication graph + SCCs), a classic contrast showing that going from 2 to 3 literals crosses the boundary.

Cook–Levin theorem: SAT is NP-complete. Hence every problem in NP reduces to SAT.

Proof sketch

  • SAT ∈ NP: certificate = assignment; evaluate the formula in linear time.
  • NP-hardness: let L ∈ NP be decided by a nondeterministic TM M in time p(n). The computation is a p(n) × p(n) tableau of configurations (tape cell contents, head position, state). Introduce Boolean variables xi,j,s = "cell i at time j holds symbol s". Write clauses saying: (a) each cell holds exactly one symbol; (b) row 0 encodes input w; (c) each 2×3 window of the tableau is a legal move of M's transition relation (local checks suffice because a TM step changes only O(1) cells); (d) the last row contains the accepting state. The formula has O(p(n)²) size, is built in poly time, and is satisfiable iff M accepts w.

The formula-building function f is a reduction L ≤p SAT for every L ∈ NP. (Textbooks often go via Circuit-SAT, then Circuit-SAT → SAT with one variable per gate: for g = a ∧ b use (¬g∨a)(¬g∨b)(g∨¬a∨¬b).)

SAT ≤p 3-SAT

Clause (l1 ∨ … ∨ lk): k=1: (l ∨ a ∨ b)(l ∨ ¬a ∨ b)(l ∨ a ∨ ¬b)(l ∨ ¬a ∨ ¬b) with fresh a,b. k=2: (l1∨l2∨a)(l1∨l2∨¬a). k>3: chain with fresh yi: (l1∨l2∨y1)(¬y1∨l3∨y2)…(¬yk−3∨lk−1∨lk). Correctness: if some lj is true, set the y's true before position j and false after, satisfying every piece; conversely if all li are false, y1 must be true, forcing y2, and so on, so the last clause fails. Size grows by a constant factor.

4. Reduction chain: 3-SAT → Clique → Independent Set → Vertex Cover

Definitions (G = (V,E), integer k). Clique: k vertices pairwise adjacent. Independent Set (IS): k vertices with no edge among them. Vertex Cover (VC): k vertices touching every edge. All three are in NP (certificate: the vertex set, checked in O(n²)).

4.1 3-SAT ≤p Clique

Construction. Formula φ with m clauses C1..Cm, three literals each. One vertex per literal occurrence (3m vertices), grouped in m triples. Join two vertices by an edge iff they are in different clauses and are not contradictory (not x and ¬x). Set k = m.

Correctness. (⇒) A satisfying assignment makes at least one literal true in each clause; pick one such vertex per clause. They lie in different clauses and no two contradict (all are true under one assignment), so they are pairwise adjacent: a clique of size m. (⇐) A clique of size m has no two vertices in the same clause (no edges inside a triple), so exactly one per clause. They are pairwise consistent, so set each chosen literal true (unmentioned variables arbitrary); every clause then has a true literal. Size: 3m vertices, O(m²) edges, poly time.

Example. φ = (x ∨ y ∨ z)(¬x ∨ ¬y ∨ z)(x ∨ ¬z ∨ y), m=3. Choose z from C1, z from C2, y from C3: z–z (different clauses, not contradictory), z–y and z–y fine: a triangle, so φ is satisfied by z=T, y=T.

4.2 Clique ≤p Independent Set

Take the complement graph Ḡ (edge iff non-edge in G); keep k. S is a clique in G ⇔ S is an independent set in Ḡ (all pairs are edges in G ⇔ no pair is an edge in Ḡ). Computable in O(n²).

4.3 Independent Set ≤p Vertex Cover

Lemma: S is an independent set of G ⇔ V∖S is a vertex cover of G. So G has an IS of size k ⇔ G has a VC of size n−k. The reduction is (G,k) ↦ (G, n−k).

Proof: S independent ⇔ no edge has both ends in S ⇔ every edge has at least one end in V∖S ⇔ V∖S is a cover. Every step is an equivalence, so both directions hold. Hence the chain 3-SAT ≤ Clique ≤ IS ≤ VC makes Clique, IS and VC NP-complete (each is also in NP).

Pitfalls: k changes (k → n−k) for VC. In 3-SAT→Clique, forgetting the "different clause" condition would let a clique grab two literals from one clause. IS on bipartite graphs is in P (König's theorem / matching), so hardness needs general graphs.

5. Subset Sum

Problem. Given positive integers a1..an and target T, is there a subset summing exactly to T? In NP (certificate = the subset). Solvable by DP in O(nT), which is pseudo-polynomial (T is exponential in its bit-length), so there is no contradiction with NP-completeness; such problems are weakly NP-complete.

Reduction 3-SAT ≤p Subset Sum

Construction. φ has variables x1..xn and clauses C1..Cm. Build base-10 numbers with n+m digits (n variable digits, then m clause digits). For each variable xi create two numbers vi (xi true) and v'i (xi false): both have a 1 in variable digit i; vi also has a 1 in clause digit j for each clause Cj containing xi, and v'i has a 1 in clause digit j if ¬xi ∈ Cj. For each clause Cj add two slack numbers sj, s'j, each with a single 1 in clause digit j. Target T has 1 in each variable digit and 3 in each clause digit.

Correctness. Each column sums to at most 5, so no carries occur and columns are independent. (⇒) From a satisfying assignment take vi if xi = T else v'i: each variable digit gets exactly 1. Clause digit j gets between 1 and 3 from literals (≥1 because the clause is satisfied); add sj and/or s'j to reach exactly 3. (⇐) Variable digit i equal to 1 forces exactly one of vi, v'i, defining an assignment. Clause digit j must reach 3 but slacks give at most 2, so at least one literal number contributes to digit j: clause j is satisfied. There are 2n+2m numbers of n+m digits: polynomial.

Example

φ = (x1 ∨ ¬x2) (a 2-literal clause is fine: slack still tops up to 3). Columns (x1, x2, C1): v1 = 101, v'1 = 100, v2 = 010, v'2 = 011, s = s' = 001, T = 113. Assignment x1=T, x2=F: v1 + v'2 = 101 + 011 = 112; add one slack 001 to get 113 ✓.

6. Hamiltonian Cycle

Problem (HAM-CYCLE). Does directed (or undirected) G contain a simple cycle visiting every vertex exactly once? In NP (certificate: the cyclic order). Compare Eulerian circuit (every edge once), which is in P via degree conditions.

Reduction 3-SAT ≤p Directed Ham Cycle (sketch of the standard gadgets)

  • For each variable xi: a row of vertices with edges in both directions, plus a start si and end ti. The row is traversed left-to-right (xi = true) or right-to-left (xi = false). Rows are chained (ti → si+1) and the last returns to the first. Each row has 3 vertices per clause (plus separators) so each clause gets its own private adjacent pair.
  • For each clause Cj: one extra vertex cj. For each literal in Cj, link that variable's private pair u, w with u→cj→w in the orientation matching the literal (left-to-right for xi, right-to-left for ¬xi), so the detour is available only if the row is traversed in the literal-satisfying direction.

Correctness. (⇒) From a satisfying assignment, traverse each row in its variable's direction; for each clause detour once through cj via one true literal. Every vertex is visited exactly once. (⇐) A Hamiltonian cycle must visit each cj by a detour from one row, and the gadget design forces each row to be traversed wholly in one direction (otherwise vertices are skipped or repeated); read the assignment off the directions. Since every cj is visited, its clause has a true literal.

Directed → Undirected

Replace each vertex v by vin – vmid – vout (a path); each directed edge u→v becomes the undirected edge uout–vin. A directed Ham cycle exists iff the undirected one does (vmid has degree 2, so the path is traversed in order, enforcing direction).

Ham Cycle ≤p TSP

Complete graph on V, weight 1 for edges of G and 2 otherwise, budget n. A tour of cost ≤ n exists iff G has a Hamiltonian cycle. Hence decision-TSP is NP-complete; optimisation TSP is NP-hard.

Pitfall: Euler = edges (poly), Hamilton = vertices (NP-complete). Shortest path is in P; longest simple path is NP-hard (it contains Ham path).

7. Exact Cover

Problem. Given universe U and a family F of subsets of U, is there a subfamily of pairwise disjoint sets whose union is U? (Variant X3C: each set has 3 elements, |U| = 3q, need q sets.) In NP (certificate: the subfamily; check disjointness and union in poly time).

Standard route: 3-SAT ≤p 3-Dimensional Matching ≤p Exact Cover (X3C), and Exact Cover ≤p Subset Sum.

Idea for 3-SAT → Exact Cover (via 3DM)

Variable gadget: a "wheel" of alternating elements forcing a choice of either all "true" sets or all "false" sets. Clause gadget: an element covered by exactly one chosen set corresponding to a true literal, with cleanup sets to cover leftover literal elements. Exactness (no overlap, nothing uncovered) ties the choices consistently. For exams know the statement, NP membership and the Exact Cover → Subset Sum step in full.

Exact Cover ≤p Subset Sum

Let U = {1..N}, sets S1..SM. Choose base b = M+1. Define aj = Σi∈Sj bi−1 (digit 1 at position i for each element i ∈ Sj) and T = Σi=1..N bi−1 (all digits 1). Because b exceeds the number of sets, no column can carry, so a subfamily's numbers sum to T iff every element's column sum is exactly 1, i.e. each element is covered exactly once, i.e. an exact cover. This also shows Subset Sum is NP-complete from Exact Cover. Size: M numbers of N digits.

Example. U={1,2,3,4}, F={ {1,2}, {3,4}, {2,3}, {1,4} }. Exact covers: {1,2}+{3,4} and {2,3}+{1,4}. Contrast U={1,2,3}, F={ {1,2}, {2,3} }: none (they overlap on 2, and either alone leaves an element uncovered). With b=3: a = 30+31 = 4 and 31+32 = 12, T = 13; no subset sums to 13 ✓.

9. Coping with NP-hardness

Options: exact exponential algorithms (backtracking, branch and bound, subset DP such as Held–Karp TSP in O(n²2n)), special cases (trees, bipartite, bounded treewidth), approximation algorithms with provable guarantees, and heuristics (no guarantee).

10. Approximation algorithms

Approximation ratio: for a minimisation problem, A is a ρ-approximation if for every instance cost(A) ≤ ρ · OPT (ρ ≥ 1) and A runs in polynomial time. For maximisation, cost(A) ≥ OPT/ρ. PTAS: (1+ε)-approximation for each fixed ε, poly in n; FPTAS: poly in n and 1/ε.

10.1 Vertex Cover: 2-approximation

APPROX-VC(G):
    C = {}
    E' = E
    while E' is not empty:
        pick any edge (u, v) in E'
        add u and v to C
        remove from E' every edge incident to u or v
    return C

Running time O(V+E) with adjacency lists.

Theorem. APPROX-VC returns a vertex cover with |C| ≤ 2·OPT.

Proof. Feasibility: every removed edge is covered by u or v and the loop ends only when no edge remains, so C is a cover. Ratio: let A be the set of picked edges. They form a matching (after picking (u,v), all edges touching u or v are deleted, so later picked edges share no endpoint with it). Any cover, in particular an optimal C*, contains at least one endpoint of each edge of A, and these endpoints are distinct, so |C*| ≥ |A|. The algorithm outputs |C| = 2|A| ≤ 2|C*|. ∎

Example. Path a–b–c–d. Pick (b,c) first: C = {b,c} covers all edges; OPT = 2, ratio 1. Pick (a,b) first: edges ab, bc removed; then pick (c,d): C = {a,b,c,d}, size 4 = 2·OPT, showing the factor 2 is tight for this algorithm (also for Kn,n-style instances).

Pitfalls: Greedily choosing the highest-degree vertex gives only an O(log n) ratio. 2 is the best known constant (2 − ε is hard under the Unique Games Conjecture). The lower bound is a maximal matching, not the cover itself.

10.2 Other examples

  • Metric TSP, 2-approx: build an MST, take a preorder walk, shortcut repeated vertices. Cost ≤ 2·MST ≤ 2·OPT (triangle inequality). Christofides improves to 3/2. General TSP has no constant-factor approximation unless P = NP.
  • Set Cover, greedy: repeatedly pick the set covering most uncovered elements; ratio Hn ≈ ln n.
  • Makespan scheduling, list scheduling: 2 − 1/m; LPT gives 4/3.
  • Knapsack: FPTAS by scaling profits and running the DP.
  • Max-3SAT: a random assignment satisfies 7/8 of clauses in expectation.

11. Heuristic algorithms

Heuristics give good solutions fast but no provable guarantee on quality (sometimes none on running time either). Typical ones:

  • Greedy construction (nearest-neighbour for TSP: repeatedly go to the nearest unvisited city; can be arbitrarily bad in the worst case).
  • Local search / hill climbing: start from a solution and repeatedly move to a better neighbour (e.g. 2-opt for TSP: replace two edges to remove a crossing) until a local optimum; can get stuck.
  • Simulated annealing: accept worse moves with probability e−Δ/T, lowering T gradually to escape local optima.
  • Genetic algorithms, tabu search, branch and bound, SAT solvers (DPLL/CDCL): work well in practice on structured instances.

Quick revision

  • A ≤p B: poly-time f with x ∈ A ⇔ f(x) ∈ B; reduce FROM a known hard problem TO the new one.
  • NP = poly-time verifiable; NPC = NP ∩ NP-hard; P ⊆ NP; P vs NP open.
  • Cook–Levin: SAT is NP-complete (computation tableau → CNF of size O(p(n)²)).
  • 3-SAT → Clique: vertex per literal, edges between different clauses and consistent literals, k = m.
  • Clique ↔ IS via complement graph; IS ↔ VC via S ↦ V∖S, k ↦ n−k.
  • Subset Sum: digit construction with slack numbers, no carries; DP O(nT) is pseudo-polynomial (weakly NPC).
  • Ham Cycle: variable rows (direction = truth) + clause vertices; directed→undirected via 3-vertex split; Ham Cycle ≤ TSP.
  • Exact Cover → Subset Sum with base M+1 digits; Exact Cover is NPC.
  • APPROX-VC: take both ends of an arbitrary uncovered edge; picked edges form a matching so |C| = 2|M| ≤ 2·OPT; tight.
  • Metric TSP: MST + preorder walk = 2-approx; greedy Set Cover = ln n; heuristics (local search, annealing) have no guarantees.
