T3 — Dynamic Programming

Principles of DP, WIS on paths, weighted interval scheduling, paths in DAGs, LIS, edit distance, 0/1 knapsack, matrix chain, rod cutting, optimal BST. Ref: DPV Ch.6, CLRS Ch.14, KT Ch.6, Erickson Ch.3.

1. Principles of dynamic programming

Idea. Solve a problem by expressing it through a recurrence over a small family of subproblems, solving each distinct subproblem once, and storing the result. DP = recursion + reuse of answers (equivalently: shortest/longest path in a DAG of subproblems).

Two requirements

  • Optimal substructure: an optimal solution contains optimal solutions to subproblems (cut-and-paste argument: if a sub-solution were improvable, improve the whole).
  • Overlapping subproblems: the number of distinct subproblems is small (polynomial) although the recursion tree is huge.

Recipe

  1. Define the state precisely (what does OPT(i, j, ...) mean?).
  2. Write the recurrence with base cases, covering every choice for the last decision.
  3. Choose an evaluation order (topological order of the subproblem DAG) or memoise.
  4. Read off the answer; store choices to reconstruct the solution (traceback).
  5. Time = (#states) x (work per state). Space = table size (often reducible).

Memoisation vs tabulation

Top-down (memo)Bottom-up (table)
Stylerecursion + cacheloops in dependency order
Subproblems solvedonly those reachedall
Overheadrecursion stacknone; easy space optimisation
Fib(n): // memoised
  if n <= 1 return n
  if memo[n] undefined: memo[n] = Fib(n-1) + Fib(n-2)
  return memo[n]

Naive Fib is T(n)=T(n-1)+T(n-2)+1 = Θ(φⁿ); memoised: n states, O(1) each, so O(n).

Pitfalls. Memo key missing a parameter (wrong answers); state that does not make subproblems independent; confusing DP with greedy (greedy commits without trying alternatives); forgetting base cases.

2. Maximum Weight Independent Set on a path

Problem. Path v1..vn with weights w_i ≥ 0. Choose pairwise non-adjacent vertices of maximum total weight.

Let M[i] = optimum for prefix v1..vi. Either vi is out (M[i-1]) or vi is in, which excludes v(i-1) (M[i-2] + w_i).

M[0]=0; M[1]=w1
for i = 2..n: M[i] = max(M[i-1], M[i-2] + w_i)
// traceback: i=n; while i>=1: if M[i-1] >= M[i-2]+w_i then i-- else {take i; i -= 2}

Correctness: induction on i using the two exhaustive cases. Time/space: O(n), O(n) (O(1) if only the value is needed).

Example: w = 4,1,1,9,3,6 gives M = 0,4,4,5,13,13,19; chosen set {v1, v4, v6} = 19.

Pitfall. Greedy (pick the heaviest, delete neighbours) fails: path 3,4,3 has optimum 6, greedy gets 4.

3. Weighted Interval Scheduling

Problem. Jobs j with start s_j, finish f_j, value v_j. Choose pairwise non-overlapping jobs maximising total value (the unweighted case is solved by greedy, the weighted one is not).

Sort by finish time f1 ≤ ... ≤ fn. p(j) = largest i<j with f_i ≤ s_j (0 if none). Then

OPT(0)=0
OPT(j) = max( v_j + OPT(p(j)),  OPT(j-1) )
sort by finish; compute p(j) by binary search
for j = 1..n: OPT[j] = max(v[j] + OPT[p[j]], OPT[j-1])

Correctness: if j is used, all other chosen jobs are compatible with j and finish before it, i.e. lie among 1..p(j) (and an optimal choice there is OPT(p(j))); otherwise the answer is OPT(j-1). Time: O(n log n) sort + O(n log n) for p + O(n) DP = O(n log n).

Example (start,finish,value) sorted: (1,4,3),(3,5,2),(0,6,4),(4,7,5),(3,8,6),(5,9,3),(6,10,2),(8,11,4). p = 0,0,0,1,0,2,3,5; OPT = 3,3,4,8,8,8,8,12 (jobs 1,4,8).

Pitfall. Unmemoised recursion is exponential. Use p(j) not j-1 when job j is chosen.

4. Shortest and longest paths in DAGs

Idea. In a DAG, process vertices in topological order; when v is processed, all of its in-neighbours are final.
topologically sort G (DFS, O(V+E))
dist[s]=0, dist[others] = +inf  (use -inf and max for longest)
for u in topological order:
  for each edge (u,v,w): dist[v] = min(dist[v], dist[u] + w)   // max for longest

Time Θ(V+E); handles negative weights; longest path = same with max (or negate weights), which is easy only because there are no cycles (in general graphs longest simple path is NP-hard). Many DPs are paths in a subproblem DAG: LIS, edit distance, and so on.

Example: edges S→A 3, S→B 2, A→C 4, A→D 1, B→C 1, B→D 6, C→T 2, D→T 3. Order S,A,B,C,D,T. Shortest: A=3,B=2,C=3,D=4,T=5. Longest: A=3,B=2,C=7,D=8,T=11 (S-B-D-T).

Pitfall. Dijkstra is unnecessary here and is wrong for negative edges; the order of processing must be topological.

5. Longest Increasing Subsequence (LIS)

Problem. Given a[1..n], find the longest subsequence with strictly increasing values.
for j = 1..n:
  L[j] = 1 + max{ L[i] : i<j, a[i]<a[j] }   (max of empty set = 0)
answer = max_j L[j]

L[j] = length of the longest increasing subsequence ending at j (a longest path in the DAG with edges i→j for i<j, a[i]<a[j]). Time O(n²), space O(n); keep a predecessor array for traceback.

Faster O(n log n): keep tails[k] = smallest last value of an increasing subsequence of length k; tails is increasing, so each a[j] is placed with binary search (replace the first tail ≥ a[j], or append).

Example: 5,2,8,6,3,6,9,7 gives L = 1,1,2,2,2,3,4,4; LIS length 4 (2,3,6,9).

Pitfall. The answer is max over all L[j], not L[n]. Subsequence is not contiguous; the tails array is not itself an LIS.

6. Edit Distance

Problem. Minimum number of insertions, deletions and substitutions turning x[1..m] into y[1..n].

D[i][j] = distance between prefixes x[1..i], y[1..j].

D[i][0]=i; D[0][j]=j
D[i][j] = min( D[i-1][j] + 1,            // delete x_i
               D[i][j-1] + 1,            // insert y_j
               D[i-1][j-1] + (x_i != y_j) )  // match / substitute

Answer D[m][n]. Time O(mn); space O(mn), or O(min(m,n)) for the value only (Hirschberg recovers the alignment in linear space). Traceback from (m,n) gives the alignment. The grid is a DAG whose paths are alignments.

Example CAT to CUT: row 0: 0 1 2 3; C: 1 0 1 2; A: 2 1 1 2; T: 3 2 2 1. Distance 1. SUNDAY to SATURDAY = 3.

Pitfall. Wrong base row/column; adding 1 on a match; confusing with LCS (LCS allows only insert/delete).

7. 0/1 Knapsack

Problem. Items with weights w_i and values v_i, capacity W. Choose a subset of total weight ≤ W maximising value; each item at most once.
K[0][c]=0 for all c
for i=1..n: for c=0..W:
  K[i][c] = K[i-1][c]
  if w_i <= c: K[i][c] = max(K[i][c], K[i-1][c-w_i] + v_i)
answer K[n][W]

Time/space O(nW); one row suffices if c runs downwards. This is pseudo-polynomial: W is exponential in its bit length log W; the problem is NP-hard in general. Unbounded knapsack uses K[c] = max(K[c-w_i]+v_i).

Example: W=7, items (w,v) = (1,1),(3,4),(4,5),(5,7). Last row (c=0..7): 0,1,1,4,5,7,8,9; optimum 9 with weights 3+4.

Pitfalls. Ratio greedy fails (W=50: (10,60),(20,100),(30,120) greedy 160, optimal 220); ascending c loop in 1D version reuses items; O(nW) is not polynomial.

8. Matrix Chain Multiplication

Problem. Matrices A1..An, Ai of size p(i-1) x p(i). Choose the parenthesisation minimising scalar multiplications (multiplying a x b by b x c costs abc).
m[i][i]=0
for len=2..n: for i=1..n-len+1:
  j=i+len-1; m[i][j]=inf
  for k=i..j-1:
    q = m[i][k] + m[k+1][j] + p[i-1]*p[k]*p[j]
    if q < m[i][j]: m[i][j]=q; s[i][j]=k

Optimal substructure: the last multiplication splits at some k, and each side must itself be optimal. Time Θ(n³), space Θ(n²). Number of parenthesisations is the Catalan number C(n-1), exponential (14 for 5 matrices). Use s[][] to print the parenthesisation.

Example p = 10,20,30,40,30: m[1,2]=6000, m[2,3]=24000, m[3,4]=36000, m[1,3]=18000, m[2,4]=48000, m[1,4]=30000 for ((A1A2)A3)A4.

Pitfall. This only chooses the order; the matrices themselves are not multiplied in the DP. Loop by increasing chain length so smaller intervals are ready.

9. Rod Cutting

Problem. Rod of length n, price p_i for a piece of length i. Cut to maximise total revenue.
r[0]=0
for j=1..n: r[j] = max over i=1..j of ( p[i] + r[j-i] )

Time Θ(n²), space Θ(n); the naive recursion has 2^(n-1) cut patterns. Store the first cut s[j] for reconstruction. It is an unbounded knapsack with weight = length.

Example prices 1,5,8,9,10,17,17,20: r = 0,1,5,8,10,13,17,18,22; r(8)=22 (2+6). Prices 2,5,7,8: r(4)=10 (2+2).

Pitfall. Selling uncut or the best price-per-unit piece is not always optimal; cutting cost, if any, must be subtracted per cut.

10. Optimal Binary Search Trees

Problem. Sorted keys k1<...<kn with search probabilities p_i. Build the BST minimising expected search cost Σ p_i (depth_i + 1).
w(i,j) = p_i + ... + p_j
e(i,i-1) = 0
e(i,j) = min over r=i..j of ( e(i,r-1) + e(r+1,j) ) + w(i,j)
fill by increasing j-i; store root[i][j]=r

Hanging two subtrees under root r pushes every key one level down, hence + w(i,j). Time O(n³) (O(n²) with Knuth's monotonicity root(i,j-1) ≤ root(i,j) ≤ root(i+1,j)), space O(n²). The general version adds probabilities q_i for unsuccessful searches in the dummy leaves.

Example p = 0.34, 0.08, 0.58: optimum root k3, then k1, then k2 gives 0.58 + 2(0.34) + 3(0.08) = 1.5; the balanced tree with root k2 costs 1.92.

Pitfall. Highest-probability key as root is not optimal in general; cost is not the sum of just subtree costs, w(i,j) must be added.

Quick revision

  • DP needs optimal substructure + overlapping subproblems; time = #states x work per state.
  • Memoisation = top-down cache; tabulation = bottom-up in topological order.
  • WIS path: M[i]=max(M[i-1], M[i-2]+w_i). Weighted intervals: OPT(j)=max(v_j+OPT(p(j)), OPT(j-1)), O(n log n).
  • DAG shortest/longest path: one pass in topological order, O(V+E).
  • LIS: L[j]=1+max L[i]; O(n²), or O(n log n) with tails + binary search.
  • Edit distance: three-way min, O(mn); knapsack: O(nW) pseudo-polynomial, row i-1 for 0/1.
  • Matrix chain O(n³), Catalan many parenthesisations; rod cutting O(n²); optimal BST O(n³), add w(i,j).
  • Greedy fails on weighted intervals, 0/1 knapsack, WIS.
